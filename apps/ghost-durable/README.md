## Runtime process

`src/main.js --root PATH --mode fixture|broker` speaks newline-delimited JSON on stdin/stdout. Its first stdout frame is a handshake containing `protocol_version: "ghost-lifetime/1"`, `contract_revision: 1`, and the pinned runtime identity. Each subsequent input frame receives one shared lifetime `Response` frame, in order. Startup/runtime diagnostics go only to stderr; stdout is reserved for protocol frames.

Runtime packaging must preserve `ghost-durable/src`, its pinned package files and `node_modules`, plus the sibling paths `ghost-ui/server/bridge.mjs` and `ghost-omp/completion-codec.mjs`. The runtime imports those siblings by relative path; copying only this package directory is not a complete deployment. Freeze native worker bridge sources separately and point the runner at that frozen entry, not a mutable checkout.

The revision-1 envelope and digests are unchanged. Existing Pi methods remain available; the Host Pi outbox additionally sends the frozen `conversation.input` body `{ method, ghost_id, conversation_id, turn_id, prompt, privacy, attachments }`. The Node boundary validates that additive body against the canonical contract, including 65,536 UTF-8 prompt bytes and 16 Artifact references, without opening a locator. The authenticated Host transport, not `actor_ref`, determines identity.

Each Ghost has an exclusive `runtime.sqlite` command index and a process lock. Each `(ghost_id, conversation_id)` maps deterministically to its own Pi Durable SQLite file. Both the index and each Pi file use the actual upstream `openNodeSqliteDatabase` adapter. The adapter's `synchronous=NORMAL` default is overridden on that same connection with `PRAGMA synchronous=FULL`; `synchronous` and `journal_mode` are read back before `SqliteStorage.open` or any runtime use. `SqliteStorage` receives that same configured adapter. No second SQLite connection is used to claim FULL durability.

The runtime lock is an OS-backed exclusive file lease. A competing live owner fails closed. The kernel releases the lease when the owner exits or is killed; recovery does not unlink a lock based on a PID guess.

`conversation.inspect` returns a fresh committed view without waking model work. `conversation.input` durably acknowledges `queued` with `submission_id: null`, the existing Pi binding/view, and the immutable original request ID before model submission. One per-conversation background scheduler admits queued turns in order; the JSONL handler never waits for earlier inference. `runtime.reconcile` reads committed state and wakes that scheduler; it processes persisted cancellation intent before any resumed submission. Watch frames may be coalesced; they are not the authority or a replay queue.

`conversation.status` adds the exact original receiver `request_id`. It reads the pinned SDK's committed submission through that same owned SQLite connection and returns bounded identity, submission ID and `queued|placed|done|unanswered` status—no transcript, raw error or model resumption. Terminal tasks can be absent from Harness's active inspection graph; that omission never proves success. Host correlates status with its durable receiver receipt, exposes unanswered/no-assignment blockers, and never automatically retries a failed generation.

## Pi integration boundaries

The package registers only the frozen `ghost-host-tools` action space: `work_submit`, `work_inspect`, `work_steer`, `work_cancel`, `goal_inspect`, `goal_create`, `goal_update`, `registry_inspect`, `work_delegate`, `work_wait`, `work_children`, `ghost_message`, and `ghost_messages`. It does not install Pi's `CodingTools`, shell, bash, read, write, or edit extensions. Model schemas exclude Host identity, actor, epoch, token, root, endpoint, and worker-spec fields. `goal_create` accepts only `prompt` and `acceptance_spec`; trusted turn and Ghost/conversation identity are runtime-owned. Mailbox send injects the closed-over Ghost as sender and selects `public` or conservative `local_only` disclosure from trusted runtime scope; mailbox reads never acknowledge messages.
The separate `memory_search`, `memory_recall`, `memory_session_list`, `memory_retain`, and `memory_session_record` tools are exposed only from Host-returned `memory.capabilities` names for the current committed Owner turn, rechecked before execution. Public inference receives none; the capability handshake is runtime-only.

The package exports `openGhostRuntime({ root, mode, modelProvider, hostToolTransport })`. Its Host callback receives `{ method, invocation_id, ghost_id, conversation_id, inference_scope, conversation_disclosure, arguments }` and Pi cancellation context; scope is injected by the runtime, never model parameters. Trusted `turn_id` is closed over for `goal.create`, `conversation.reply`, owner-scoped memory capability checks, and the internal `conversation.turn_status`/`conversation.turn.inspect` controller callbacks; these status/inspection methods are not model tools. The configured entrypoint captures `GHOST_PI_CALLBACK_TOKEN` and the positive `GHOST_PI_AUTHORITY_EPOCH` once per process. A local route, when configured, receives a separate optional `GHOST_PI_LOCAL_CALLBACK_TOKEN`; it is never used for model HTTP. `GHOST_LIFETIME_WORKER_MODEL` must equal `openai-codex/gpt-6-luna`; public WorkerSpec uses thinking `max`, `canary-local`, `canary_read`/`canary_write`, the work-hash workspace, and the frozen deadline/progress caps.
Host discovery uses the existing bootstrap HMAC only to verify the bound Host; `/api/v1/pi/action` receives the public Pi callback credential, never the owner bearer. Local-scoped callbacks use only `/api/v1/pi/local-action` and the separate local credential. Both paths retain the same `PiToolRequest` R1 envelope and closed-over Ghost actor, conversation, and captured authority epoch. Stable v2 callback command IDs include Ghost, conversation, SDK invocation, and method. Worker execution IDs remain `pi-<sha256(invocation_id)>`; before `work.submit`, current work is inspected and an existing handle is returned without a new attempt. Historical v1 owner-proxy receipts and Pi SDK storage are left unchanged.

Fixture mode uses the real pinned Pi Durable Harness and pi-ai's upstream `fauxProvider`; it is not a custom imitation of the SDK. Broker mode uses pi-ai's OpenAI Completions adapter over the existing OMP `auth-gateway stdio` process and, when valid local configuration is present, a separate loopback-only `ghost-local` provider.

- `GHOST_MODEL_REF`: `provider/model` identity that must appear in `GHOST_OMP_SUBSCRIPTION_MODELS`.
- `GHOST_OMP_EXECUTABLE`: absolute path to the OMP executable.
- `GHOST_OMP_SUBSCRIPTION_MODELS`: comma-separated provider/model allowlist, matching the Host's existing subscription-model configuration.

Each model request launches one OMP process with `--no-extensions --no-rules --no-skills --no-session --config <private-temp-config> auth-gateway stdio`. The adapter sends `{ id, path: "/v1/chat/completions", body }` with `body.stream = false`, consumes the readiness and matching `{ id, status, body }` response frames, and converts the OpenAI completion to SSE for pi-ai. The child receives only `HOME`, a bounded system `PATH`, private `TMPDIR`, and `NO_COLOR`; OMP retains its own credentials. Request, stdout, stderr, and process time are bounded; retries and provider fallback are disabled. B1 source work does not invoke the gateway.

The custom fetch closure is installed in the live provider's `stream`/`streamSimple` adapters, not `settings.stream`: Pi 1.1.0 copies generation settings into a strict-JSON request. The SDK-facing loopback transport key is a non-credential placeholder; only OMP resolves provider credentials, and model request bodies contain no transport key.

### Explicit private local route

Local inference is selected only for a conversation whose committed disclosure is `non_public`; it is not a fallback for failed public calls. Configure `GHOST_LIFETIME_LOCAL_MODEL_URL` and `GHOST_LIFETIME_LOCAL_MODEL_ID` together. The canary pin is `http://127.0.0.1:8768/v1` and `mlx-community/Qwen3.6-35B-A3B-4bit`. The URL must be a canonical literal IPv4/IPv6 loopback HTTP(S) `/v1` base with no credentials, query, fragment, DNS alias, or remote host. Every request pins `POST /chat/completions` and the configured model, rejects redirects, sends no auth header, uses a default 1,024-token output cap (Owner startup configuration `GHOST_LIFETIME_LOCAL_MAX_OUTPUT_TOKENS` accepts integers 1–4,096; invalid explicit values refuse startup), a 180-second timeout, a bounded 4 MiB JSON response, and zero retries. Accept the native SDK's positive safe-integer output budget up to that cap, not only exact equality. The local descriptor uses a bounded 16,384-token client context window, below the pinned model config's 262,144-token capability; this is not long-context server acceptance. Pi-ai1.1.0 retains its native context budgeting and 4,096-token safety reserve. Truncated/empty output remains an error; reasoning-disabled metadata or template flags do not prove the actual model stops thinking. The Host captures the local endpoint, model and output limit together and passes a nonsecret configuration digest to the Pi process. Each new Goal assignment pins that configuration at durable admission; a changed configuration blocks inference on the old assignment after reopen. Legacy assignments without a route pin retain only the historical 1,024-token compatibility path; a larger bound requires a fresh authorized assignment.

On an explicit public→local transition, the runtime quiesces prepared public Pi tasks and submissions, then calls `root.configure({ model: { provider, modelId } }, context)` on the same conversation root. It preserves Ghost/Pi conversation IDs and durable entries. It checks committed privacy immediately before each public broker invocation. Unknown disclosure cannot start or resume generation; an empty bootstrap can create storage but does not invoke a model. Missing or invalid local configuration returns a protected-route blocker with no public fallback.

The separate `GHOST_PI_LOCAL_CALLBACK_TOKEN` authorizes only local-scoped Host actions. Local mailbox sends are marked `local_only`. Local `work.submit` and `work.steer` require a current Host-issued NativeComputer grant that explicitly permits the Goal's protected privacy and a keyless local HTTP model backend. Subscription-native grants are public-only. Missing or mismatched grants fail before Worker dispatch; a local failure never falls back to an external provider. This source contract does not itself accept a live private native Worker run.

Host integration requires both `GHOST_LIFETIME_PI_ENTRY` and explicit `GHOST_LIFETIME_MODE=fixture|broker`; an unset mode is rejected. `GHOST_LIFETIME_WORKER_SOCKET` points to the independent supervisor's private Unix socket. Use a root short enough for the platform's native Unix-socket path limit. Neither process installs or restarts operating services.

Each conversation records the most restrictive disclosure observed: `private`/`local_only` submissions become sticky `non_public`. Public conversations continue through the configured broker. Non-public conversations use the explicitly configured loopback local provider; later `public` input does not upgrade them. Canonical input first commits trusted intent and sticky privacy, then returns its queued acknowledgement; the background scheduler selects the committed public/local route before any provider request. Legacy submit/steer and reconciliation likewise check committed privacy before model work. Unknown disclosure cannot start or resume generation, and no route failure falls back to a different provider. Privacy comes from the committed Ghost conversation and trusted Host envelope, not model flags. Legacy Rust/oxicode conversations are not imported or transformed.

## Canonical owner conversation

The Host commits the user turn and sticky disclosure before enqueueing Pi `conversation.input`. The Node runtime atomically persists the trusted `turn_id`, disclosure, original command/request ID, prompt, and opaque Artifact references with a `queued` run row before acknowledging; `submission_id` remains `null` until the scheduler commits the real SDK submission using that original request ID. Retries reuse the same turn, request, and Pi conversation identities. Artifacts are validated and retained without opening their locators or forwarding locator text to the model. The current Pi adapter has no authorized Artifact resolver, so attachment contents are not model input.

`goal_create` sends only model `prompt`/`acceptance_spec` plus runtime-derived `turn_id`, Ghost, and conversation. The Host derives privacy and ownership from the owner turn, enforces its four-Goal limit, and returns Goal/Work facts with `origin_turn_id`; Goal creation is not acceptance. Existing Goal-driven `conversation.submit` and report paths remain distinct; legacy submit/steer cannot interleave with an unresolved canonical turn.

An existing authenticated Goal assignment can inspect its exact Goal/Work,
submit only that Work, delegate only from it, and wait only on it. Coordination
requires the same current assignment; Host ownership, revisions, graph limits
and privacy remain authoritative. A structured incident operations policy binds
the delegate to its Host-inspected approved operations Ghost. Assignment turns
still cannot create/update Goals, cancel/steer Work, access personal memory,
send mailbox messages, or publish Owner replies/acceptance. Work-report model
requests remain read-only.

Only the transport's typed pre-submit missing-native-grant rejection reports
`host_effect_class: no_effect`. Other thrown callback/receipt failures remain
effect-unconfirmed and do not expose raw diagnostics; inspect the original
identity rather than issuing a replacement mutation.

Cancellation targets the exact four-field `{method, ghost_id, conversation_id, turn_id}` body; there is no no-target alias. Its ACK durably reports `cancel_requested: true` only; it does not wait for model settlement, and `conversation.turn_status` reports completion separately. The Host and Pi persist the cancellation intent. A queued never-submitted turn becomes cancelled without inference. A running turn is rechecked under the shared transition gate and aborted only through its exact pinned Pi Durable submission/generation task; the gate is released before settlement waiting, and the next submission waits for quiescence. Accepted Host Work handles are never cancelled or erased by controller cancellation.

`conversation.turn_status` reports the actual controller observation (`running`, `answered`, `failed`, `cancelled`, or `effect_unknown`) with only bounded SDK IDs and frozen reason codes. The runtime persists the exact payload, deterministic invocation ID, digest, and receipt before each mutation callback. Unknown callback outcomes use a fresh read-only `conversation.turn.inspect` invocation, then reuse only the original immutable status invocation/payload. Status facts contain no prompt or raw provider/exception text; they are separate from the original advisory `conversation.reply`.

Host `conversation.inspect` projects `turn_runs` only for runs referenced by its returned Owner/source-turn page, and preserves `cancel_requested` as a JSON boolean. The internal `conversation.turn.inspect` read is bounded to its exact Ghost/conversation/turn target.

After a Pi Durable input settles `done`, the runtime reads its committed terminal `AssistantEntry` and projects text through authenticated `conversation.reply`. The deterministic invocation identity includes Ghost, conversation, Pi conversation, and entry ID. The Host transport pages canonical `conversation.inspect` first; a matching immutable `assistant_advisory` receipt ends recovery, while an absent reply is retried with the same invocation ID. This advisory is never an acceptance or verified completion. Pending projection identity/digest/receipt live in the scoped Ghost index; explicit `runtime.reconcile` recovers unknown outcomes without replaying the model turn or rewriting cached responses. Older unanswered/blocked rows are inspected by original SDK request ID and status; an absent submission remains `effect_unknown`, never replaced.

Canonical failed/cancelled/effect-unknown observations use the internal Host status callback and never emit a synthetic assistant message. `model_request_failed` describes the pinned SDK's terminal model error; it does not claim provider unavailability. The status reason is bounded and excludes raw prompt, token, exception, and provider text. Root owns Host migration 012 and endpoint/whitelist/read-only hooks; integrated execution and acceptance remain coordinator gates.

The Host observes its owned Pi child exiting or confirmed transport closure, restarts that runtime, and performs fresh read-only reconciliation. Observations use new command IDs; mutations retain their immutable IDs. A cold nonterminal SDK submission that this process did not admit is observed as `effect_unknown` with the original submission ID, never waited on, resumed, or replaced. Exact cancellation can settle it without another inference.

Root's isolated source12 canary exercised real local replies, queued cancellation without an SDK submission, desktop running cancellation with discarded late output, stale-target isolation, and a Pi process crash after model I/O with no reexecution. A new Owner turn also used both actual Note retention and Session recording: the owned engine persisted two Untrusted Primary sources with raw UTF-8 SHA-256 matching the Host ledger. These observations do not accept private guest OMP, physical phone/voice, full cold restore, or the entire product.

## Fixture conformance source

`test/fake-provider.js` scripts the actual upstream provider. Existing behavioral source coverage includes immutable command replay and conflicts, privacy-tainted reopen through the local route, public-generation disclosure guards, scoped local Host invocation, local endpoint/model/response rejection, explicit pending-tool crash recovery without repeating a committed external effect, OS-backed exclusive ownership, and broker generation transport kept outside strict-JSON settings.
