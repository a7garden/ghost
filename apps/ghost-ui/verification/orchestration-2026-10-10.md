구현 범위: 협업 화면의 `협업 기록` / `작업 구조` 전환, 작업 그래프 편집, owner API 저장·실행·취소, 호스트 스케줄러 실행, 불변 실행 구조, 작업별 결과와 대화 링크. Garden 0.1.0의 기존 vendored `GPanel`과 `Card`를 사용했다.

## 자동 검증

- `cargo check` 및 `cargo check --features workspace-ui`: 통과.
- `cargo test --lib --features workspace-ui`: 99개 통과.
- `cargo build --bin ghost --features workspace-ui,lifetime`: 통과.
- `npm test`: Vitest 35개 파일의 180개 테스트와 bridge 테스트 10개 통과.
- `npm run build`: 통과. 기존 500 kB 이상 chunk 안내는 남아 있다.

호스트 테스트는 병렬 시작·합류, 성공·실패 조건, 실행 구조 보존, 오래된 버전 거부, 취소 후 후속 작업 차단, 접수 응답 유실 시 동일 제출 복구를 확인한다. 불확실한 결과가 종료 상태와 연결 조건으로 취급되지 않는 경계도 확인한다. 프런트엔드 테스트는 그래프 계층, 순환·중복·유효하지 않은 담당 Ghost 거부, UTF-8 바이트 제한, 실행 스냅샷 정규화를 확인한다.

## 브라우저 검증

분리된 임시 루트의 실제 호스트(`mock` 모델)와 UI `http://127.0.0.1:5187`를 사용했다. 기존 사용자 호스트와 데이터는 재시작하거나 변경하지 않았다. 실제 외부 모델·도구 호출은 포함하지 않는다.

1. Research와 Review를 담당 Ghost로 지정해 두 병렬 작업, 두 결과를 받는 합류 작업, 실패 조건 작업을 작성하고 저장했다.
2. 새로고침 후 버전 1 구조가 복원됐다. 실행 시작 직후 두 시작 작업이 실행 중, 합류·실패 작업이 선행 작업 대기로 표시됐다.
3. 시작 작업 두 개와 합류 작업이 완료되고 실패 분기는 조건 불일치로 표시됐다. 합류 상세의 실제 Mock 출력에 두 선행 결과가 모두 포함됐다.
4. 순환 연결을 추가하면 저장이 거부되고 설명이 표시됐다. 해당 연결을 제거한 뒤 제목을 수정해 버전 2로 저장했다.
5. 새로고침 후 저장된 버전 2와 이전 실행의 버전 1을 각각 확인했다. 과거 실행을 볼 때 편집·실행 버튼은 `저장된 구조 편집` / `저장된 구조 실행`으로 표시한다.
6. 작업 상세에서 `작업 대화 열기`를 누르면 실제 담당 Ghost의 해당 작업 대화가 열렸다.
7. 기존 협업 기록 화면과 작업 구조 화면 간 전환을 확인했다.
8. 1280×720 편집창은 1120px 너비로 표시됐다. 375×812에서는 설정 패널이 연결도 아래로 배치되고, 문서 너비 375px / 편집창 너비 343px로 뷰포트 가로 넘침이 없었다. 연결도는 자체 스크롤을 사용한다. 편집창 하단 닫기도 동작했다. 검증 후 뷰포트 설정을 복원했다.

브라우저 검증 중 공통 `.modal` 규칙이 편집창 너비를 덮는 문제와 담당 Ghost 선택 레이블 문제를 고쳤고, 수정 후 다시 확인했다.
