# PC와 mini의 Ghost 인수 준비

2026-10-22 KST. iPhone은 이번 범위에서 제외했다. **현재 정본 writer는 여전히 Studio이며, mini의 실제 운영 데이터 복원본은 epoch 2 / dispatch off다.** ZAI 인증의 mini 연결은 소유자가 승인했다. 기존 Primary 대화의 제공자별 이력 허용은 Codex뿐이므로, 동일 이력의 ZAI 처리에 대한 별도 응답을 기다린다. 단독 canary 성공을 정본 cutover 완료로 표시하지 않는다.

## 구현

- `ghost lifetime fence --host-root … --expected-epoch … --operation-id … --confirm`은 실제 workspace lock을 획득한 뒤 활성/불명 업무를 거절하고, 현재 epoch를 CAS 검사해 다음 epoch와 dispatch off를 원자적으로 기록한다. 같은 operation ID는 원 영수증을 회수한다. worker/broker의 별도 fence ACK를 대신하지 않는다.
- `GHOST_WORKER_RELOCATION_FILE`은 `ghost-worker-relocation/1`의 소유자 전용 설정이다. 현재 workspace와 복원 epoch, 원래 Ghost/computer/worker root를 대사한다. 겹치는 경로·심볼릭 링크·공개 권한을 거절한다. 과거 command/spec/receipt/locator bytes와 digest는 보존하고, 원래 worker artifact store의 읽기 경로만 새 저장소로 연결한다. 파일명이나 digest를 완화하지 않는다.
- 복구 묶음의 기본 한도 512MiB는 유지한다. `GHOST_RECOVERY_MAX_BYTES`를 명시하면 512MiB–16GiB 안의 한도로 스트리밍 capture/verify/restore를 실행한다. 실제 primary worker 장부가 약 2GiB여서 이번에는 4GiB를 선택했다. 번들 형식과 기본 거부 시험은 유지한다.
- `computers rebind`는 현재 binding epoch와 expected grant revision으로 다음 binding을 제안하도록 고쳤다. `accept-runtime`은 등록 과정에서 실제로 관측한 kind와 executable SHA-256 전체를 전달한다. 실제 registry의 rebind→runtime acceptance→dispatch readiness와 stale/다른 해시 거절을 시험했다.
- 처음 발화하기 전에도 Owner가 이미 등록된 정확한 Ghost/conversation 쌍의 제공자를 선택할 수 있다. foreign pair는 거절한다. 키·외부 이력 허용·개인 기억/문서 권한은 여전히 별개다.
- guest의 broker/완성 응답 거절은 upstream status와 안전한 reason을 갖는 adapter 422 응답으로 전달한다. SDK 내부 재시도에도 broker 교환은 한 번이며 원 거절을 보존한다. 네트워크 없는 실제 pinned Linux SDK에서 upstream 429·잘린 completion·성공을 검증했다.
- 데스크톱 `host_mode: external`은 HMAC으로 기존 Host를 확인한 뒤 UI만 띄운다. 연결 실패 때 새 writer를 만들지 않고, 종료할 때 외부 Host를 종료하지 않는다. 패키징에는 UI bridge가 사용하는 형제 `ghost-omp` 모듈도 포함한다.

`oxi-frontmatter`의 형제 저장소가 0.4.0이므로 Cargo/lock을 정렬했다. PDC의 형식 권위·v1 가독성·원문 보존 경계를 유지하며 사용자 파일을 변환하거나 다시 저장하지 않았다.

## 실제 검증

운영 Host/Pi·네 worker·computer registry·전용 home/browser를 실제 정지 상태에서 6개 root로 capture했다. 2,109,958,562 bytes / 1,488 files를 검증한 뒤 Studio 서비스를 원래 판본으로 복귀시켰고 기존 turn/Goal/Work/registry 사실을 대사했다. mini 복원에서 DB integrity 67개, 모든 파일 digest와 네 home의 `lane_isolated`를 확인했다. provider credential 값은 복구 묶음에서 제외했다.

mini의 별도 신규 canary는 Studio 모델/worker 터널 없이 직접 ZAI 구독을 사용했다. 실제 Linux Node24.20.0/Python3.13.16이 합계·SHA-256·SQLite를 계산하고 407-byte artifact를 게시했다. verifier는 Goal의 봉인 recipe, 실제 bash call/stdout, authenticated artifact bytes/digest와 실제 runtime을 대사했다. 원 revision1 accepted, 같은 Primary 보고 2개, 재개 전후 native execution 1개를 확인했다. 초기 보고 조회 harness의 column 오류는 원 성공 업무를 재실행하지 않고 검사만 수정해 회수했다.

mini 복원본의 네 worker는 epoch 2 fence를 ACK하고 epoch 1 mutation을 거절했다. 네 computer의 epoch 2 재바인딩과 관측 runtime acceptance를 완료했다. `lifetime accept`의 확인 없는 preview는 나머지 readiness 조건을 통과한 뒤 정확히 `--confirm`에서 거절됐다. dispatch는 계속 꺼져 있다.

실제 SSH loopback link에서 HMAC과 workspace ID, 0600 discovery, CLI snapshot 회수·자기 소유 tunnel의 정상 종료를 검증했다. 정본 Studio root는 이 시험에 연결하지 않았다. PC 앱은 기존 정본의 같은 workspace/9 profiles를 읽는다. 실제 패키지 probe와 외부 Host를 건드리지 않는 종료를 확인했고 예전 app-owned Host process는 0개다. 예전 `Ghost Provider R2` 데이터와 앱·설정 복귀본을 보존했다.

## 운영 경계와 다음 실행

정본 cutover 전에는 새 primary 대화의 ZAI 이력 허용을 기록하고, 최신 Source 상태를 다시 대사해야 한다. Studio Host의 실제 정지·영속 fence와 네 worker/broker 차단을 확인한 뒤 mini만 dispatch를 연다. PC는 새 writer를 띄우지 않는 SSH link로 바꾸고 앱·gateway의 현재 epoch/토큰을 회수한다. 기존 artifact의 실제 relocation read, canonical 대화, Host 재시작·토큰 갱신·중복 실행 부재를 다시 확인한다.

현재 일일 Restic entry는 로컬 Host가 로컬 destination에 snapshot을 만드는 구조다. mini 정본 전환 시 이 경로의 원격 snapshot/export와 worker/home 포함 범위를 함께 연결해야 한다. 로컬 경로를 mini 서버에 그대로 보내는 방식은 사용하지 않는다. 현재 두 호스트의 검증된 cold bundle은 새 ACK의 주기적 백업이나 집 밖 사본을 대신하지 않는다.

ZAI proxy의 `local_http`는 loopback transport이며 실제 inference는 클라우드다. 10/20 소유자 결정의 기존 worker 경로를 재사용했다. 로컬 비공개 추론·금융 원장 전송 허용·개인 기억/문서 권한이 추가됐다고 주장하지 않는다. mini Codex binary는 공식 기존 실행 파일을 로컬 ad-hoc 서명해 실행했고, Codex OAuth 토큰을 읽거나 복사하지 않았다.

실제 mini 재부팅/FileVault preboot·무인 로그인과 기간 관찰은 아직 미검증이다. iPhone·APNs·음성·Google·집 밖 저장소는 이번 PC–mini 준비의 수용 증거가 아니다.

상세 영수증과 운영 복귀 위치는 infra의 `reports/2026-10-22/ghost-dual-host-preparation.md`를 따른다. 기존 대규모 dirty 소스 중 이번 headless runtime 검증에 필요한 lifetime/Pi/worker/contract/test 기반은 출처를 구분해 함께 버전으로 보존하며, 이 문서의 신규 수정과 이전 구현 전체를 같은 세션의 신규 저작으로 합치지 않는다.
