새 React 콘솔 `apps/ghost-ui`를 Rust 호스트에 연결하고, 사용자가 제공한 Z.ai
인증으로 실제 모델·도구·문서 승인·협업·재시작 복구를 검증했다.
콘솔은 `http://127.0.0.1:62062/`에서 실행 중이다.

## 실제 호출에서 발견하고 수정한 실패

1. **HTTP 429:** Ghost의 정적 모델 정보는 Coding Plan 주소였지만 SDK 제공자
   카탈로그가 전송 주소를 일반 API로 덮어썼다. `GhostProviders`에서 Coding Plan
   주소를 명시적으로 고정했다. 직접 호출 성공, 수정 전 SDK HTTP 429, 수정 후
   실제 도구 호출 성공 순서로 확인했다.
2. **빈 응답으로 완료:** Oxicode가 도구 호출 조각을 `ToolCallEnd` 이벤트로
   조립하면서 `Done.message`에는 넣지 않았다. durable 실행기가 최종 메시지를
   읽으므로 도구가 실행되지 않았다. 완성된 도구 이름·ID·인자를 최종 메시지에
   포함하도록 고치고 HTTP 회귀 테스트에서 검사한다. 사용량도 HTTP 청크 사이에
   유지하도록 수정했다.

초기 실패 기록은 원래 대화에 남아 있다. 성공 기록으로 덮어쓰거나 삭제하지 않았다.

Z.ai 공식 문서는 일반 API와 Coding Plan 주소를 구분하며, 현재 Coding Plan에서
5.1 요청을 5.3으로 라우팅한다고 명시한다.
[API 인증·주소](https://docs.z.ai/api-reference/introduction),
[Coding Plan 모델 안내](https://docs.z.ai/devpack/overview).

## 실행과 인증

```sh
cargo build --features workspace-ui
npm --prefix apps/ghost-ui run build
npm --prefix apps/ghost-ui run console
```

개인 설정 `~/.config/ghost/console.json`에는 상태 폴더·모델·인증 파일 경로·UI
포트만 저장한다. 이 Mac의 상태 폴더는
`~/Library/Application Support/Ghost`다. 키는 프로젝트 밖의 소유자 전용
`0600` 인증 파일에 저장하며, UI 서버에는 인증 환경변수를 전달하지 않는다.
프로젝트·UI 배포 파일·호스트 DB/WAL 등 1,981개 파일에서 제공된 키가
저장되지 않았음을 검사했다. 자세한 설정은 [콘솔 README](../apps/ghost-ui/README.md)를 따른다.

명시적으로 한 번 더 모델을 진단하려면 다음 명령을 사용한다. 실제 호출을 수행한다.

```sh
GHOST_LIVE_PROBE=1 GHOST_MODEL=zai/glm-5.1 \
GHOST_AUTH_FILE=/absolute/private/path/zai-auth.json cargo run --example model_probe
```

## 검증 수치와 범위

자동 테스트 **702개 통과**: UI 21, 브리지 7, Ghost 라이브러리 37,
durable/workspace 통합 8, Oxicode 제공자 라이브러리 621, HTTP 제공자 통합 8.
Ghost와 Oxicode 제공자의 엄격한 Clippy, UI production 빌드 및 별도의 mock
브리지 통합 검사도 통과했다. 개별 로그와 바이너리·수정 소스 해시는 위 JSON에 있다.

실제 호스트의 누적 보고 사용량은 **40,607 토큰**, 모델 전송 시도는 15회다.
여기에는 진단 중 HTTP 429 세 번과 수정 전 빈 최종 메시지 한 번이 포함된다.
호스트 밖 진단 요청의 보고 사용량은 별도로 86 + 148 토큰이며, 계정 전체 사용량을
조회한 값은 아니다. Z.ai 정적 카탈로그의 USD 가격은 0 자리표시자여서 실제 금액은
측정하지 않았다. 요청·토큰 예산으로 제한하며 0 USD를 무료라고 해석하지 않는다.

이번 실제 계정 검증 범위는 Z.ai와 로컬 문서·협업이다. Slack, 음성, 원격 컴퓨터,
외부 MCP 계정 및 배포의 실서비스 검증은 별도다.
