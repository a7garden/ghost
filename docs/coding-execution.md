# 코딩 실행

Ghost는 일을 끝까지 책임지고, 코딩 에이전트는 herdr에서 코드를 쓴다. Host는 별도 코딩 실행기나 모델을 띄우지 않는다. 이 설계는 2026-11-22 소유자가 승인했다.

시작은 효과, 관찰은 읽기, 완료 보고는 대화 깨움이다. 이 세 가지를 긴 도구 호출 하나에 묶지 않는다.

## 책임

| 구성 | 책임 |
| --- | --- |
| 담당 Ghost | 목표·경계·완료 기준 전달, 변경 검토, 직접 실행한 검사 영수증 확보, 저장소 규칙에 따른 통합 |
| 맡긴 일(`Work`) | 책임자, 권한, 실행 예산, 결정, 검증, 최종 결과 |
| 코딩 실행(`CodingRun`) | 맡긴 일과 herdr terminal의 연결, 지시한 턴과 보고한 턴, 복구·중단 상태 |
| herdr | 작업 공간·worktree·pane·에이전트 실행, 관측 가능한 상태와 기록 |
| 소유자 | 에이전트 권한 다이얼로그 응답, 예산 연장·중단, 기존 규칙이 요구하는 결과 수용 |

코딩 에이전트는 새 Ghost나 하위 맡긴 일이 아니다. 에이전트가 쓴 명령과 완료 주장은 Ghost의 검사 영수증을 대신하지 못한다. 기존 `complete` → 검사 → 검토 → 소유자 수용 순서를 유지한다.

## 도구

`code_agents {pane?}`는 연결 준비 상태와 에이전트 목록을 읽는다. 떠 있는 에이전트에는 세션·pane·상태·경로와 연결된 맡긴 일을 표시한다. pane을 지정하면 질문·마지막 응답·git 변경을 제한된 크기로 읽는다. 출력은 지시가 아닌 신뢰하지 않는 관측 자료다.

읽기에도 현재 Ghost의 도구 허용과 PC 실행 권한을 검사한다. Work 대화에서는 PC 실행 대상과 추가 도구 범위도 따른다. Host가 terminal을 만들었다는 `owned` 표시는 보기 권한이 아니다. 소유자가 직접 연 에이전트도 같은 PC 권한 아래 읽을 수 있다.

`code_run {repo? | pane?, task, agent?, branch?}`은 프롬프트가 접수되면 실행 주소를 반환한다. `timeout_minutes`는 사용하지 않는다. 새 실행은 herdr가 만든 worktree와 브랜치에서 시작한다. pane을 지정하면 같은 대화에 후속 지시를 보낸다. 작업 중·응답 대기·상태 불명인 pane에 새 지시를 보내지 않는다. 기존 pane을 넘겨받을 때도 소유자의 체크아웃이 격리되었다고 가정하지 않는다.

하나의 terminal은 동시에 하나의 맡긴 일만 쥔다. 실행 하나에 열린 턴은 하나이며, 같은 맡긴 일의 한 시도에서 보낼 수 있는 지시는 실행들을 합쳐 최대 네 턴이다. 새 실행을 만드는 것으로 재시도 한도를 우회할 수 없다. 기존 Work 예산과 도구 반복 보호도 유지한다.

## 시작과 복구

1. 도구 호출의 결정적 식별자로 실행 의도를 원장에 남긴다. 실제 쓰기는 기존 효과 저널과 정책을 거친다.
2. workspace가 열리면 pane·terminal·세션·checkout·브랜치·기준 커밋을 저장한다. 에이전트 실행과 프롬프트 직전에 현재 권한·맡긴 일·턴을 다시 검사한다.
3. 프롬프트 전송 의도를 기록하고 전송한다. 접수는 완료가 아니다. 도구는 에이전트의 전체 작업 시간을 기다리지 않는다.
4. 감시기는 원장의 열린 실행을 읽어 관측을 갱신한다. 세션 설정이 바뀌어도 저장한 세션을 관찰한다. 같은 pane 주소에 다른 terminal이나 에이전트가 나타나면 기존 실행을 잃은 것으로 처리한다.
5. 완료·실종·시작 불확실 보고는 맡긴 일의 원래 대화에 `run:<id>:turn:<n>`처럼 결정적인 id로 제출한다. 보고 내용을 먼저 고정하고 제출 성공 뒤 전달 표시를 남긴다. 그 사이에 재시작되어도 같은 보고와 id를 다시 제출한다.

재시작은 프롬프트를 재전송하지 않는다. workspace 생성과 주소 저장 사이에서 끊기면 결과는 불확실하다. 읽어서 확인하거나 새 단계로 소유자가 명시적으로 진행해야 하며, 시작이 실패했다고 추측해 두 번째 에이전트를 띄우지 않는다.

`idle`이나 `done`이라는 상태값만으로 턴 완료를 확정하지 않는다. 지원하는 herdr에서는 전송 직전 `completion_seq`와 비교해 새로운 작업 완료 전이가 있는지 확인한다. 이 필드가 없는 서버는 지시 뒤 `working`을 본 다음 `idle` 또는 `done`으로 돌아온 관측을 사용한다. 빠른 턴이나 재시작 사이의 관측 공백은 전송 전 기록 위치 이후의 고유 지시 표식과 에이전트 응답으로 보완한다. 주인이 다른 지시를 보냈으면 그 응답을 원래 일의 결과로 가로채지 않는다. 근거가 없으면 시작 정체·불확실로 보고하며 성공으로 꾸미지 않는다. `blocked`는 같은 턴의 소유자 응답 대기다.

## 대기·예산·중단

열린 코딩 실행은 하위 일·결정·질문에 이어 맡긴 일의 네 번째 대기 이유다. Ghost 대화가 끝나도 실행 중인 에이전트가 있으면 idle 독촉이나 자동 실패를 만들지 않는다. 완료 보고를 전달할 때 원래 맡긴 일의 시도와 현재 권한을 재확인한다. 취소·재개·검토로 넘어간 옛 시도의 보고가 새 시도를 깨우면 안 된다.

Ghost 대화와 코딩 에이전트가 일하는 시간의 합집합을 같은 Work 실행 예산으로 센다. 동시에 일한다고 두 번 과금하지 않고, 소유자 답만 기다리는 시간은 제외한다. 별도 두 시간짜리 코딩 타이머는 두지 않는다. 소유자가 정한 기한도 에이전트가 일하는 동안 적용한다. 실제 관측 간격보다 정밀한 에이전트 사용 시간 계측을 보장하지 않는다.

맡긴 일 취소·권한 회수·예산 정지는 기록된 terminal과 에이전트가 여전히 같은지 확인하고 중단을 요청한다. pane·worktree·브랜치는 지우지 않는다. 중단 요청의 불확실성을 이유로 새 턴에 키 입력을 반복하지 않는다. Host 정상 재시작·업데이트는 코딩 에이전트를 종료하지 않으며 원장의 실행을 다시 관찰한다.

## 보고와 화면

완료 보고에서 에이전트의 마지막 말은 **주장**이고, git에서 읽은 커밋·diff·미커밋 상태는 **관측**이다. omp·Claude Code의 구조화된 대화 기록을 먼저 사용하고, 읽을 수 없는 에이전트는 터미널 끝부분이라는 출처를 명시한다. 도구 출력 전체나 생각 내용을 모델 맥락으로 복제하지 않는다.

원격 게시 관측은 로컬 remote-tracking ref와 upstream만 읽는다. 네트워크 조회를 하지 않으므로 ref가 오래되었을 수 있다. ref의 존재는 해당 에이전트가 push했다는 증거가 아니고, 부재도 push하지 않았다는 증거가 아니다. worktree는 쓰기 격리이지 보안 샌드박스가 아니며 push·merge 금지 지침을 강제하는 장치도 아니다.

메인은 기존 `work_list`·`work_inspect`에서 실행 상태를 확인하고 담당 Ghost에게 방향을 전달한다. 코딩 탭은 담당 맡긴 일로, 맡긴 일 상세는 해당 pane으로 연결한다. 실행 결과는 먼저 담당 Work 대화로 돌아가며 메인의 자율 깨움 한도를 사용하지 않는다. 최종 결과는 기존 팀 보고 경로를 따른다.

관리 중인 실행의 완료는 맡긴 일 보고와 겹쳐 주인에게 별도 완료 알림을 만들지 않는다. 권한 다이얼로그는 주인에게 남긴다. 모델 도구에는 원시 키 입력이나 다이얼로그 응답을 노출하지 않는다.

## 선택하지 않은 구조

- **코딩 에이전트를 하위 Work로 취급:** Pi 대화 없이 `complete`·질문·검증을 흉내 내는 두 번째 실행·검증 경로가 필요하다.
- **효과 결과 JSON에서 실행을 전부 파생:** 전송 전 턴 예약, 독점, 중단 의도와 전달 위치를 트랜잭션으로 관리할 수 없다. 작은 `coding_runs` 표 하나가 이 상태의 정본이다.
- **모든 완료를 메인 자율 깨움으로 전송:** 담당 책임을 우회하고 자율 깨움 예산을 소모한다.
- **에이전트별 감독 봇·두 번째 scheduler:** 기존 Work·효과·감시·Pi 제출로 충분하다.

## 수용 기준

- 준비·조회만으로 프롬프트가 전송되지 않으며 도구·PC 권한 없는 호출은 거절된다.
- 지시 접수 뒤 Ghost 대화가 반환되고 에이전트가 계속 일한다. 완료 뒤 같은 맡긴 일이 한 번 이어진다.
- 전송 직후 idle, 빠른 응답, blocked 후 재개, 세션 변경, terminal 재사용을 성공으로 오인하지 않는다.
- 재시작 전후 프롬프트 중복·보고 중복이 없고 다른 시도의 대화를 깨우지 않는다.
- 코딩 실행 중에는 예산이 흐르고 소유자 답 대기에는 멈춘다. 취소·회수·예산 정지는 결과물을 보존한다.
- Ghost가 diff와 직접 실행한 check를 확인한 뒤 기존 검증 경로로 결과를 제출한다.
- 코딩 화면과 맡긴 일 사이를 실제로 오갈 수 있다.
