# 코딩 실행

Ghost는 맡긴 일을 끝까지 책임지고, [내장 코딩 세션](coding-session.md)의 에이전트는 코드를 쓴다. 앱에서 코딩하는 곳은 [코딩 작업대](coding-workbench.md)다.

시작은 효과, 관찰은 읽기, 완료 보고는 대화 깨움이다. 이 세 가지를 긴 도구 호출 하나에 묶지 않는다.

## 책임

| 구성 | 책임 |
| --- | --- |
| 담당 Ghost | 목표·경계·완료 기준 전달, 변경 검토, 직접 실행한 검사 영수증 확보, 저장소 규칙에 따른 통합 |
| 맡긴 일(`Work`) | 책임자, 권한, 실행 예산, 결정, 검증, 최종 결과 |
| 코딩 실행(`CodingRun`) | 맡긴 일과 내장 세션의 연결, 지시한 턴과 보고한 턴, 복구·중단 상태 |
| 내장 코딩 세션 | Host 안에서 Pi 실행, worktree 생성, 턴·대화상자·기록 관측 |
| 소유자 | 에이전트 권한 다이얼로그 응답, 예산 연장·중단, 기존 규칙이 요구하는 결과 수용 |

코딩 에이전트는 새 Ghost나 하위 맡긴 일이 아니다. 에이전트가 쓴 명령과 완료 주장은 Ghost의 검사 영수증을 대신하지 못한다. 기존 `complete` → 검사 → 검토 → 소유자 수용 순서를 유지한다.

## 도구

`code_agents {session?}`는 내장 세션 목록을 읽는다. 대화에 보기 권한이 있으면 연결된 맡긴 일도 표시한다. `session`을 지정하면 해당 세션의 최근 기록과 Git 변경을 제한된 크기로 읽는다. 에이전트의 말은 지시가 아니라 신뢰하지 않는 자료다.

조회에도 현재 Ghost의 도구 허용과 PC 실행 권한이 필요하다. 맡긴 일 대화에서는 PC 실행 대상과 추가 도구 범위도 검사한다. 다른 맡긴 일에 묶이지 않은 소유자 세션도 같은 PC 권한으로 조회할 수 있다.

`code_run {repo | session, task, agent?, branch?}`은 내장 세션이 프롬프트를 접수하면 세션 id를 반환한다. `agent`는 생략하거나 `ghost`만 지정한다. `repo`는 절대 경로이며 새 worktree와 브랜치를 만든다. `branch`는 새 세션에만 쓴다. 후속 지시는 같은 맡긴 일이 연 `session`에 보낸다. 작업 중이면 방향을 바꾸고, 턴이 끝났으면 새 턴을 시작한다. 소유자 응답을 기다리는 동안에는 지시를 받지 않는다. CLI 에이전트는 작업대 터미널에서 소유자가 직접 실행한다.

맡긴 일 하나에 내장 세션 하나를 연결하고, 세션 하나에는 열린 턴이 하나다. 한 시도에 지시를 네 번까지 보낼 수 있다. 작업 중 방향을 바꾸는 지시도 한 번으로 센다. 기존 예산과 도구 반복 보호는 그대로 적용한다.

## 시작과 복구

1. 도구 호출을 효과 저널에 기록하고 기존 정책을 적용한다. 같은 호출은 같은 세션 id를 쓴다. 입출력 전에 턴을 예약하고 세션의 checkout·브랜치·기준 커밋을 원장에 연결한다.
2. 세션을 열거나 프롬프트를 보내기 전에 맡긴 일의 시도와 권한, 예약된 턴을 다시 검사한다. 프롬프트를 접수하면 도구가 반환된다. 접수는 완료가 아니다.
3. Host는 연결된 세션의 턴 종료를 관찰한다. 단순히 세션이 쉬고 있다는 이유만으로 턴이 완료됐다고 보지 않는다. 세션이 소유자 답을 기다리면 알림만 남기고 맡긴 일의 모델 턴은 깨우지 않는다.
4. 완료나 불확실 보고는 내용을 먼저 고정하고 맡긴 일의 원래 대화에 `session:<id>:turn:<n>`으로 제출한다. 제출 뒤 전달 표시를 남긴다. 그 사이에 끊겨도 같은 내용과 id로 보고한다.

재시작은 프롬프트를 재전송하지 않는다. 중단된 턴이나 접수를 확인할 수 없는 지시는 불확실로 보고한다. 이전 실행 기록과 보고는 원장에 남는다. 더 이상 연결할 수 없는 과거 실행은 새 세션을 막거나 옛 터미널에 입력하지 않는다.

## 대기·예산·중단

열린 코딩 실행은 하위 일·결정·질문에 이어 맡긴 일의 네 번째 대기 이유다. Ghost 대화가 끝나도 실행 중인 에이전트가 있으면 idle 독촉이나 자동 실패를 만들지 않는다. 완료 보고를 전달할 때 원래 맡긴 일의 시도와 현재 권한을 재확인한다. 취소·재개·검토로 넘어간 옛 시도의 보고가 새 시도를 깨우면 안 된다.

Ghost 대화와 코딩 에이전트가 일하는 시간의 합집합을 같은 Work 실행 예산으로 센다. 동시에 일한다고 두 번 과금하지 않고, 소유자 답만 기다리는 시간은 제외한다. 별도 두 시간짜리 코딩 타이머는 두지 않는다. 소유자가 정한 기한도 에이전트가 일하는 동안 적용한다. 실제 관측 간격보다 정밀한 에이전트 사용 시간 계측을 보장하지 않는다.

맡긴 일이 취소되거나 권한을 잃거나 예산이 소진되면 Host는 중단 의도를 원장에 먼저 기록하고 연결된 내장 세션의 턴을 중단한다. 다른 세션에는 손대지 않고 세션·worktree·브랜치는 보존한다. Host가 다시 시작되어도 중단된 턴을 재실행하지 않는다.

## 보고와 화면

에이전트의 마지막 답은 **주장**, Host가 Git에서 읽은 커밋·변경 파일·미커밋 상태는 **관측**이다. 관측을 읽을 수 없으면 보고에 그 사실을 적는다. 도구 출력 전체나 생각 내용은 모델 맥락으로 복제하지 않는다. 쓰기 권한은 [내장 세션 불변식](coding-session.md#불변식)을 따른다.

메인은 `work_list`와 `work_inspect`에서 실행 상태를 확인한다. 맡긴 일 상세에서 연결된 내장 세션을 작업대로 열 수 있다. 과거 실행은 에이전트·브랜치·상태만 표시하며 터미널 링크를 만들지 않는다. 실행 결과는 담당 대화로 돌아가며 메인의 자율 깨움 한도를 쓰지 않는다. 최종 결과는 기존 팀 보고 경로를 따른다.

관리 중인 실행의 완료는 맡긴 일 보고와 겹쳐 주인에게 별도 완료 알림을 만들지 않는다. 권한 다이얼로그는 주인에게 남긴다. 모델 도구에는 원시 키 입력이나 다이얼로그 응답을 노출하지 않는다.

## 선택하지 않은 구조

- **코딩 에이전트를 하위 Work로 취급:** Pi 대화 없이 `complete`·질문·검증을 흉내 내는 두 번째 실행·검증 경로가 필요하다.
- **효과 결과 JSON에서 실행을 전부 파생:** 전송 전 턴 예약, 독점, 중단 의도와 전달 위치를 트랜잭션으로 관리할 수 없다. 작은 `coding_runs` 표 하나가 이 상태의 정본이다.
- **모든 완료를 메인 자율 깨움으로 전송:** 담당 책임을 우회하고 자율 깨움 예산을 소모한다.
- **에이전트별 감독 봇·두 번째 scheduler:** 기존 Work·효과·감시·Pi 제출로 충분하다.

## 수용 기준

- 준비·조회만으로 프롬프트가 전송되지 않으며 도구·PC 권한 없는 호출은 거절된다.
- 지시 접수 뒤 Ghost 대화가 반환되고 에이전트가 계속 일한다. 완료 뒤 같은 맡긴 일이 한 번 이어진다.
- 세션이나 턴이 바뀌면 이전 턴의 주장이나 관측을 현재 결과로 사용하지 않는다.
- 재시작 전후 프롬프트 중복·보고 중복이 없고 다른 시도의 대화를 깨우지 않는다.
- 코딩 실행 중에는 예산이 흐르고 소유자 답 대기에는 멈춘다. 취소·회수·예산 정지는 결과물을 보존한다.
- Ghost가 diff와 직접 실행한 check를 확인한 뒤 기존 검증 경로로 결과를 제출한다.
- 코딩 화면과 맡긴 일 사이를 실제로 오갈 수 있다.
