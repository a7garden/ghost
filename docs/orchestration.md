# Ghost 작업 구조

React UI의 **협업 → 작업 구조**에서 구조를 만들고 저장·실행한다. 기존 협업 기록은 실제 위임 메시지를 조회하는 화면으로 유지한다. 작업 구조는 사용자가 지정한 작업 그래프이며, 기존 위임 관계를 자동으로 변환하지 않는다.

## 편집과 실행

- 작업마다 이름, 담당 Ghost, 요청 내용을 지정한다. 작업 카드를 누르면 설정을 연다.
- 선행 작업을 선택하고 `성공하면`, `실패하면`, `성공·실패 모두` 중 시작 조건을 정한다.
- 선행 작업이 없는 작업은 병렬로 시작한다. 선행 작업이 여러 개이면 모두 종료하고 모든 연결 조건을 충족해야 시작한다.
- 조건에 맞지 않는 작업은 건너뛴다. 건너뜀과 취소는 성공·실패 조건을 충족하지 않는다.
- 결과가 불확실하면 후속 작업을 실행하지 않는다. 해당 작업의 대화를 열어 기존 호스트의 확인 절차를 사용한다.
- 구조 실행 기록에서 각 작업의 상태, 결과, 대화를 열 수 있다. 실행 중 취소하면 미접수 후속 작업을 차단하고 이미 접수된 작업의 취소를 요청한다. 결과 확인이 필요한 작업은 확정될 때까지 취소 확인 중으로 남을 수 있다.

구조당 작업 1~16개, 연결 64개를 지원한다. 구조 이름과 작업 이름은 각각 200바이트, 요청 내용은 4000바이트 이내다. 순환 연결, 중복 연결, 존재하지 않는 담당 Ghost를 거부한다. 첫 버전의 연결 편집은 설정 폼으로 제공한다.

같은 구조는 한 번에 하나만 실행할 수 있다. 실행 시 구조 전체와 버전을 복사하므로 이후 저장된 구조를 수정해도 실행 중인 작업과 이전 기록은 바뀌지 않는다. 수정과 실행 요청에는 현재 버전을 보내며 충돌하면 최신 구조를 다시 열어야 한다.

각 작업은 담당 Ghost의 현재 모델·정책에 맞는 새 대화에서 실행된다. 준비된 설정과 입력은 접수 전에 보존한다. 선행 결과는 참고 자료로 전달하며 입력 전체를 8192바이트로 제한한다. 이 한도를 넘는 선행 결과는 UTF-8 문자 경계를 유지하며 작업별로 나눠 줄인다. 결과 조회용 출력은 작업당 최대 8192문자다.

## 저장과 복구

구조와 실행은 `workspace.db`의 journal에 `orchestration_plan`, `orchestration_run` 레코드로 저장한다. 준비된 설정과 입력은 `orchestration_config`, `orchestration_input`에 저장한다. 이는 데이터베이스 전용 제어 기록이며 공유 문서 평면을 추가하지 않는다.

호스트 스케줄러가 실행을 진행하므로 브라우저를 닫아도 호스트가 살아 있으면 계속된다. 실행 ID와 작업 ID에서 안정적인 대화·접수 ID를 만들고, 재시도 시 실제 세션의 접수 기록을 먼저 확인한다. 접수 후 응답을 잃어도 같은 작업을 중복 제출하지 않는다.

Owner API:

| action | 입력 |
| --- | --- |
| `save_orchestration` | 신규는 `id: null`, `version: null`; 수정은 현재 ID·버전과 `plan` |
| `start_orchestration` | `plan_id`, 현재 `version` |
| `cancel_orchestration` | `run_id` |

스냅샷의 `capabilities.orchestration`과 `orchestration_plans`, `orchestration_runs`를 사용한다. 이 capability가 없는 이전 호스트에서는 저장·실행을 비활성화하고 업데이트 안내를 표시한다. 새 호스트 바이너리로 재시작해야 사용할 수 있다. 예시 모드는 구조 편집·저장만 제공하며 실행 기록을 만들지 않는다.
