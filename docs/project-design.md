# 프로젝트 설계

상태: **채택** (2026-11-24). [기반 설계](ghost-infrastructure.md) 3절의 「범위」를 화면에서 어떻게 보이게 할지 정한다. 코드의 `Scope`는 그대로이고, 이 문서는 소유자가 프로젝트 안에서 무엇을 하는지와 그에 맞춘 화면 구조를 다룬다.

## 1. 프로젝트는 무엇인가

한 가지 일거리를 위한 **방**이다. 폴더와 문서 금고, 받을 Ghost 한 명, 그 안에서 오간 대화와 맡긴 일이 한곳에 있다. 권한을 주지 않고, 조직의 모양을 정하지 않는다. 안에 프로젝트를 둘 수 없다. 기반 설계의 이 불변 조건은 그대로다.

소유자가 방에 들어가서 하는 일은 넷이다.

| 하려는 것 | 화면 |
| --- | --- |
| 말을 건다, 일을 시킨다 | 대화 |
| 지금 어떻게 돼 가는지 본다, 내 확인을 기다리는 것을 처리한다 | 맡긴 일 |
| 쌓인 자료를 읽고 쓴다 | 문서 |
| 어디로 가는지 적어 둔다 | 목표 |

그 밖의 것은 방을 어떻게 꾸렸는지에 관한 것이다. 매일 열지 않으므로 **설정** 한 곳으로 모은다.

## 2. 화면

```
┌ 비행 기록  도우미 · 프로젝트 폴더          [대화 도구]  [일 맡기기] ┐
│ 대화  맡긴 일 ②  문서  목표                                설정 │
├────────────────────────────────────────────────────────────────┤
│ 선택한 탭                                                      │
```

- **머리는 두 줄이다.** 첫 줄은 이름(눌러서 바꾼다), 받을 Ghost, 폴더 이름, 오른쪽에 「일 맡기기」. 둘째 줄은 탭이다. 설명 문장, 경로 칩, 문서 개수, 마지막 편집은 두지 않는다. 폴더 전체 경로는 이름에 마우스를 올리면 보이고 설정에 있다.
- **머리는 고정이고 아래만 움직인다.** 대화는 머리 아래를 채우고 대화창이 스스로 스크롤한다. 나머지 탭은 본문이 스크롤한다. 시트 위쪽의 40px 여백은 없다.
- **열리는 곳은 대화다.** 받을 Ghost가 있으면 대화로, 없으면 맡긴 일로 열린다. 주소의 `?view=`가 있으면 그것을 따른다.
- **대화 도구는 머리로 올라온다.** 프로필, 전화, 스레드, 일정이 「일 맡기기」 옆에 있다. 대화창 안에 따로 줄을 두지 않는다.
- **기다리는 일은 탭에 숫자로 보인다.** 맡긴 일 탭의 숫자는 이 프로젝트에서 소유자를 기다리는 확인할 일의 수다.
- **휴대전화는 이름 줄을 접는다.** 제목 표시줄이 이미 프로젝트 이름을 말하므로 머리에는 대화 도구, 「일 맡기기」, 탭만 남는다. 탭은 44px 높이로 가로로 스크롤한다.

### 맡긴 일

위에서 아래로 **확인할 일 → 진행 중 → 끝난 일**이다. 확인할 일은 전체 「확인할 일」과 같은 결정 카드이고, 이 프로젝트에 속한 것만 있다. 결정 탭은 따로 두지 않는다. 같은 것을 두 번 보여 줄 이유가 없다.

### 설정

기본 정보(이름, 받을 Ghost, 읽기 경로, 문서 금고, 상태, 붙임, 한도, 삭제)가 먼저 열리고, 위의 작은 알약 줄에서 나머지를 고른다.

| 이름 | 예전 이름 | 무엇 |
| --- | --- | --- |
| 자동 활동 | 계기 | 예약·커밋처럼 일을 시작시키는 조건 |
| 승인 규칙 | 규칙 | 어떤 행동을 허용·거부하고 누가 결정할지 |
| 성과와 비용 | 계측 | 완료율, 반려율, 일 하나의 시간과 비용 |
| 변경 기록 | 구성 기록 | 설정을 누가 왜 바꿨는지, 되돌리기 |

옛 이름은 화면과 명령 검색 어디에도 남기지 않는다. 전체 설정의 같은 화면도 같은 이름이다. 주소 `?view=triggers|rules|metrics|history|decisions`는 계속 열리고 설정 또는 맡긴 일로 간다.

## 3. 목록과 진입

프로젝트 목록의 한 줄은 이름 아래에 **받을 Ghost · 진행 중 N · 확인 필요 N**을 보인다. 멈춘 프로젝트는 앞에 「멈춤」이 붙는다. 들어가 보지 않고도 어느 방이 나를 기다리는지 안다.

## 4. 대화의 범위

프로젝트의 대화는 받을 Ghost가 소유자와 나누는 **하나뿐인 지속 대화**에 이 프로젝트를 붙여 보내는 것이다. 입력창의 프로젝트 칩이 그 표시이고 Host는 메시지마다 `scopeId`로 문서·경로·한도를 맥락에 넣는다. Ghost마다 지속 대화 하나라는 기존 구조(`GhostChat`)를 따르고, 프로젝트마다 별도 대화를 만들지 않는다.

알려진 한계: 대화창은 그 Ghost의 대화 전체를 보인다. 같은 Ghost가 받는 다른 프로젝트나 프로젝트 없는 대화의 메시지도 섞여 있고, 스레드 목록도 프로젝트로 거르지 않는다. 메시지에는 `scopeId`가 있으나 답변에는 없어 화면만으로 거를 수 없다. 거르려면 Host의 대화 읽기에 프로젝트 필터가 필요하며, 이는 별도 변경이다.

## 5. 바꾸지 않은 것

- 데이터 모델: `Scope`, 맡긴 일·결정·목표·자동 활동의 `scopeId` 귀속.
- 받을 Ghost는 하나, 한 Ghost가 여러 프로젝트를 받을 수 있다.
- 프로젝트가 없는 일은 「전체」에 속하고 기본 Ghost가 받는다.
- 권한: 프로젝트는 PC 권한을 주지 않는다. 승인 규칙은 프로젝트에 한정해 걸 수 있을 뿐이다.
