# 코딩 작업대 (herdr + omp 대체)

소유자 목표 2026-11-24: 장기적으로 herdr + omp 조합을 Ghost 하나로 대체한다. [coding-session.md](coding-session.md)의 내장 Pi 세션이 에이전트 자리이고, 이 문서는 그 둘레를 정한다. herdr 연동은 이행 기간 동안 그대로 두고, 여기서 만드는 것이 같은 일을 하게 되면 그때 걷는다(별도 결정).

## 개념

| 개념 | 뜻 |
| --- | --- |
| **스페이스(Space)** | 한 저장소(또는 디렉터리)에 묶인 작업 공간. herdr의 workspace. 저장소 스페이스는 worktree를 가질 수 있다. 프로젝트(Scope)와 별개이며 권한을 주지 않는다 |
| **탭(Tab)** | 스페이스 안의 화면 하나. 분할 배치(layout)를 가진다 |
| **패널(Pane)** | 탭의 분할 칸 하나. 종류: `session`(내장 Pi 코딩 세션) 또는 `terminal`(내장 터미널) |
| 세션 | `CodingSession`. 패널이 가리킬 뿐 패널과 수명이 다르다: 패널을 닫아도 세션은 남고 목록에서 다시 연다 |
| 터미널 | Host가 띄운 PTY. 패널과 수명이 같지 않다: 패널을 닫으면 종료, Host 재시작이면 종료 |

- 새 스페이스에서 Git 저장소를 고른 뒤 **worktree로 시작**을 켜고 브랜치 이름을 입력하면, 작업 폴더가 새 worktree로 설정된다. 기본값은 꺼짐이다. 스페이스를 삭제해도 worktree와 브랜치는 남는다.
- 작업대 헤더의 **git 변경**은 현재 스페이스의 저장소에서 변경된 파일과 줄 수를 읽고, 선택한 파일의 스테이징된 변경과 작업 폴더 변경을 나눠 보여준다. 내용을 쓰거나 스테이징하지 않는다.
- 맡긴 일의 **코딩 세션 열기**와 내장 세션의 응답 대기 알림은 작업대에서 해당 세션을 연다. 이미 열린 패널이 있으면 그 자리로 이동하고, 없으면 현재 탭에 추가한다.

## 갈래 (서로 독립, 각자 한 에이전트가 풀스택으로 맡는다)

1. **작업대(Workbench)**: 스페이스·탭·패널 모델과 영속, 분할 UI(가로·세로 분할, 크기 조절, 이동, 닫기, 단축키), 코딩 탭의 첫 화면을 이 작업대로 교체(herdr 로스터 대신 스페이스 목록 + 활성 탭), 완료·입력 대기 알림 연결.
2. **터미널(Terminal)**: Host의 PTY(`Bun.spawn` terminal), 스트리밍 WebSocket, 스크롤백, 크기 조절, 입력, xterm.js 패널, 터미널 안 에이전트(omp·claude·codex·pi) 감지와 끝남·입력 대기 감지·알림.
3. **Pi 설정과 확장(PiConfig)**: 자동 압축(compaction)·재시도·사고 수준·모델 기본값·도구 허용 같은 Pi 설정을 전역 기본값과 세션별로 설정하고, Pi 확장·스킬·프롬프트 템플릿·패키지를 소유자가 설치·켜고 끄는 생태계 지원.
4. **오케스트레이션(Orchestration)**: 소유자의 omp 구조(모델 역할, 에이전트 역할, 동시성·깊이 한도, 대체 모델 사슬)를 내장으로 옮기고, 그래프로 보고 편집하는 화면, 전체 끄기.

## 공유 규약 (모든 갈래)

- 영속은 새 SQL 마이그레이션 없이 원장 설정 저장(`ledger.setting(key)`/`putSetting`)의 JSON으로 한다. 키는 갈래별 접두어(`workbench.`, `pi.`, `orchestration.`). 터미널은 영속하지 않는다.
- API는 `/api/workbench/*`, `/api/terminals/*`, `/api/pi/*`, `/api/orchestration/*`. 인증·오류 규약은 `/api/coding/sessions`와 같다. 계약 타입은 `packages/ghost-contract/src/<갈래>.ts`에 두고 `index.ts`에 export를 한 줄 더한다.
- 갈래 사이 접점은 둘뿐이다: (a) 작업대의 `terminal` 패널은 `terminalId`만 안다(터미널 갈래가 `POST /api/terminals {cwd, command?, args?, cols, rows}` → `{id}`와 React `TerminalPane({terminalId, onExit})`를 준다), (b) 작업대의 `session` 패널은 기존 `CodingSessionScreen`을 쓴다. 설정(PiConfig)과 오케스트레이션은 내장 세션 서비스(`apps/ghost-host/src/coding/`)가 읽는 값만 노출하며, 그 서비스 수정은 각 갈래가 필요한 만큼 가산적으로 한다.
- 모든 새 도구·확장 적재·PTY·명령 실행은 소유자의 것이다. Ghost(비서)는 터미널을 열거나 확장을 설치하거나 오케스트레이션을 바꾸지 못한다(읽기 전용 조회만 허용 가능). 이를 막는 근거를 코드에 둔다.
- **새 패널 → 에이전트**는 Mac에 설치된 CLI를 골라 지정한 폴더에서 실행한다. 명령과 인수는 배치에 저장하되, Host가 다시 시작된 뒤에는 소유자가 저장한 명령을 직접 실행해야 한다. 셸 패널은 그대로 다시 열린다.
- Host 업데이트는 터미널에서 작업 중이거나 답을 기다리는 에이전트도 기다린다. 대기 중인 일반 셸은 업데이트를 막지 않는다.
- UI는 `apps/ghost-ui/AGENTS.md`·`DESIGN.md`와 agent-ui·anti-slop 규칙을 따른다: 설명 문구 최소, 타입과 여백으로 위계. 한국어 문구.
- 확장 코드는 Host 프로세스 권한으로 실행된다. 그래서 확장 설치는 소유자 전용이고 기본은 꺼짐이며, 설치 화면에 그 사실을 한 줄로 밝힌다. 세션 하나의 확장 적재 실패는 그 세션만 막는다.

## 수용 기준

- 코딩 탭에서 스페이스를 만들고, 탭을 추가하고, 패널을 가로·세로로 나눠 한쪽은 내장 세션, 다른 쪽은 터미널로 쓴다. 새로고침·Host 재시작 뒤 배치가 돌아온다. Host가 다시 시작되면 셸은 새로 열리고, 내장 세션은 이어지며, 에이전트 명령은 사용자가 다시 실행한다.
- 터미널 패널에서 셸 명령과 omp/claude/codex/pi CLI를 실행하고, 색상·커서·크기 조절·스크롤백이 동작하며, 터미널 안 에이전트가 끝나거나 입력을 기다리면 앱 알림이 온다.
- 세션 설정에서 자동 압축을 켜고 끌 수 있고 실제 세션에 적용된다. 소유자가 설치한 Pi 확장이 세션에 적재돼 도구·명령을 더한다.
- 오케스트레이션 화면에서 역할·모델 역할·대체 사슬·한도를 그래프로 보고 편집하며, 변경이 `subagent` 도구에 즉시 반영되고, 전체를 끄면 `subagent` 도구가 사라진다. omp 설정에서 가져올 수 있다.
