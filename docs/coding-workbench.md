# 코딩 작업대

2026-11-25에 소유자가 작업대를 **스페이스와 에이전트** 둘로 줄였다. 탭과 패널·분할은 없고, 터미널은 원할 때만 여는 보조 도구다(omp·claude·codex·pi를 터미널에서 띄우던 시작 양식은 없다). 에이전트는 [내장 Pi 코딩 세션](coding-session.md)을 GUI로 여는 것이다. (2026-11-24의 herdr 연동 제거와 동등성 검토는 [coding-parity.md](coding-parity.md).)

## 개념

| 개념 | 뜻 |
| --- | --- |
| **스페이스(Space)** | 한 저장소나 디렉터리에 묶인 작업 공간. 저장소 스페이스는 worktree를 가질 수 있다. 프로젝트(Scope)와 별개이며 권한을 주지 않는다 |
| **에이전트(Agent)** | 스페이스에 나열된 코딩 세션(`CodingSession`) 하나. 세션은 에이전트가 가리킬 뿐 수명이 다르다: 에이전트를 닫아도 세션은 남고 「에이전트 추가」에서 다시 연다. 세션 하나는 한 스페이스에만 있다 |

- 새 스페이스는 폴더만 고르면 폴더 이름이 스페이스 이름이 된다(이름을 적으면 그 이름). 폴더가 없는 스페이스도 만들 수 있다.
- 새 에이전트의 작업 폴더에 **샌드박스**(폴더 없음)가 있다. 폴더가 없는 스페이스에서는 기본값이다. 소유자 세션 하나마다 `~/Ghost/sandbox-<id>`에 빈 폴더를 만들어 거기서 일한다(프로젝트 없는 채팅과 같다). 샌드박스에는 worktree가 없고, Ghost(비서)의 `code_run`은 여전히 저장소가 필요하다.
- 새 스페이스에서 Git 저장소를 고른 뒤 **worktree로 시작**을 켜고 브랜치 이름을 입력하면, 작업 폴더가 새 worktree로 설정된다. 기본값은 꺼짐이다. 스페이스를 삭제해도 worktree와 브랜치는 남는다.
- 3일 넘게 움직이지 않은 대기 중·실패·닫힌 에이전트는 목록에서 「이전 에이전트 N개」로 접힌다. 보고 있는 에이전트, 작업 중·입력 대기 에이전트, 알림 표시가 있는 에이전트는 접히지 않는다. 접힌 에이전트는 마운트하지 않으며 펼치면 다시 고를 수 있다. 목록에서 지우지는 않는다.
- **터미널**은 소유자가 헤더의 「터미널」을 눌러야 열린다. 에이전트가 일하는 폴더(없으면 스페이스 폴더)에서 로그인 셸이 뜨고, 데스크톱에서는 에이전트 아래 42% 서랍으로, 휴대전화에서는 에이전트 화면을 덮는 전체 화면으로 열린다. 「숨기기」는 셸을 살려 두고 다시 열면 그 셸에 붙는다(스크롤백 복원). 「종료」가 셸을 끝낸다. 터미널은 Host 재시작 뒤 남지 않고, Ghost(비서)나 에이전트가 열 수 없다. Host 상태 폴더는 막히지만 Host가 만든 worktree는 열린다.
- 에이전트 행에서 오른쪽 클릭(터치는 「더 보기」)하면 「이름 바꾸기」와 「삭제」 메뉴가 열린다. 삭제는 목록에서만 지우며 세션 기록은 남아 「이전 세션 열기」로 다시 연다.
- 새 에이전트는 한 번에 시작 양식으로 열린다(스페이스 목록의 「새 에이전트」, 휴대전화 헤더의 +). 이미 있는 세션은 「이전 세션 열기」에서 고른다.
- 휴대전화 헤더는 한 줄이다: 보고 있는 에이전트 이름(스페이스 이름 작게)을 누르면 스페이스·에이전트 목록이 열리고, 오른쪽에 터미널·git 변경·새 에이전트 아이콘이 있다.
- 스페이스를 고르면 그 아래에 에이전트가 나열되고, 마지막으로 보던 에이전트가 열린다. 에이전트 화면은 모두 마운트된 채 숨기므로 초안과 스트림이 전환에도 남는다.
- 헤더의 **git 변경**은 현재 스페이스의 저장소에서 변경된 파일과 줄 수를 읽고, 선택한 파일의 스테이징된 변경과 작업 폴더 변경을 나눠 보여준다. 내용을 쓰거나 스테이징하지 않는다.
- 맡긴 일의 **코딩 세션 열기**와 내장 세션의 응답 대기 알림은 해당 에이전트를 연다. 이미 어느 스페이스에 있으면 그곳으로 이동하고, 없으면 현재 스페이스에(스페이스가 없으면 저장소 이름의 새 스페이스에) 추가한다.
- 2.33.x까지의 탭·패널 상태는 처음 읽을 때 에이전트로 옮긴다. 세션 패널은 탭 순서대로 에이전트가 되고 터미널 패널은 버린다.

## 구성

1. **작업대(Workbench)**: 스페이스 목록과 에이전트 목록, 에이전트 추가·닫기, 완료·입력 대기 표시.
2. **Pi 설정과 확장(PiConfig)**: 자동 압축(compaction)·재시도·사고 수준·모델 기본값·도구 허용 같은 Pi 설정을 전역 기본값과 세션별로 설정하고, Pi 확장·스킬·프롬프트 템플릿·패키지를 소유자가 설치·켜고 끄는 생태계 지원.
3. **오케스트레이션(Orchestration)**: 소유자의 omp 구조(모델 역할, 에이전트 역할, 동시성·깊이 한도, 대체 모델 사슬)를 내장으로 옮기고, 그래프로 보고 편집하는 화면, 전체 끄기.

## 공유 규약

- 영속은 새 SQL 마이그레이션 없이 원장 설정 저장(`ledger.setting(key)`/`putSetting`)의 JSON으로 한다. 키는 갈래별 접두어(`workbench.`, `pi.`, `orchestration.`).
- API는 `/api/workbench/*`, `/api/pi/*`, `/api/orchestration/*`. 인증·오류 규약은 `/api/coding/sessions`와 같다. 작업대 API는 `GET·POST /spaces`, `PATCH·DELETE /spaces/:id`, `GET /spaces/:id/changes`, `POST /spaces/:id/agents {sessionId}`, `DELETE /agents/:sessionId`, `POST /focus`이며 모든 쓰기는 `version`을 싣는다. 계약 타입은 `packages/ghost-contract/src/<갈래>.ts`에 둔다.
- 모든 새 도구·확장 적재는 소유자의 것이다. Ghost(비서)는 작업대를 조작하거나 확장을 설치하거나 오케스트레이션을 바꾸지 못한다(읽기 전용 조회만 허용 가능). 이를 막는 근거를 코드에 둔다.
- Host 업데이트는 작업 중이거나 답을 기다리는 내장 세션을 기다린다.
- UI는 `apps/ghost-ui/AGENTS.md`·`DESIGN.md`와 agent-ui·anti-slop 규칙을 따른다: 설명 문구 최소, 타입과 여백으로 위계. 한국어 문구.
- 확장 코드는 Host 프로세스 권한으로 실행된다. 그래서 확장 설치는 소유자 전용이고 기본은 꺼짐이며, 설치 화면에 그 사실을 한 줄로 밝힌다. 세션 하나의 확장 적재 실패는 그 세션만 막는다.

## 수용 기준

- 코딩 탭에서 스페이스를 만들고, 에이전트를 추가해 GUI 세션으로 쓴다. 에이전트를 여러 개 두고 전환해도 각자의 초안과 진행 상태가 남고, 새로고침·Host 재시작 뒤 스페이스·에이전트 목록과 마지막으로 보던 에이전트가 돌아온다. 터미널은 「터미널」 버튼을 눌러야만 열리고, 어떤 경로로도 저절로 열리지 않는다.
- 세션 설정에서 자동 압축을 켜고 끌 수 있고 실제 세션에 적용된다. 소유자가 설치한 Pi 확장이 세션에 적재돼 도구·명령을 더한다.
- 오케스트레이션 화면에서 역할·모델 역할·대체 사슬·한도를 그래프로 보고 편집하며, 변경이 `subagent` 도구에 즉시 반영되고, 전체를 끄면 `subagent` 도구가 사라진다. omp 설정에서 가져올 수 있다.
