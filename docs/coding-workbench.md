# 코딩 작업대

2026-11-26에 소유자가 작업대를 **프로젝트와 에이전트**로 다시 짰다. 코딩의 스페이스는 없어지고 [프로젝트(Scope)](project-design.md)가 그 자리를 맡는다. 데스크톱·웹에서는 에이전트를 나란히 여는 **패널 분할**이 있고, 탭은 없다. 터미널은 원할 때만 여는 보조 서랍이다(omp·claude·codex·pi를 터미널에서 띄우던 시작 양식은 없다). 에이전트는 [내장 Pi 코딩 세션](coding-session.md)을 GUI로 여는 것이다. (2026-11-24의 herdr 연동 제거와 동등성 검토는 [coding-parity.md](coding-parity.md).)

## 개념

| 개념 | 뜻 |
| --- | --- |
| **프로젝트(Scope)** | 앱 사이드바에서 받을 Ghost 아래에 놓인다. 코딩 중 프로젝트를 누르면 그 프로젝트의 작업대가 열린다. 경로는 새 에이전트의 작업 폴더 후보다. 프로젝트 자체는 PC 권한을 주지 않는다 |
| **프로젝트 없음** | 프로젝트에 속하지 않은 에이전트(샌드박스나 프로젝트 밖 폴더)가 있을 때 프로젝트 목록에 나타나는 항목 |
| **에이전트(Agent)** | 프로젝트에 나열된 코딩 세션(`CodingSession`) 하나. 세션은 에이전트가 가리킬 뿐 수명이 다르다: 목록에서 지워도 세션은 남고 새 에이전트 화면의 「이어서 하기」에서 다시 연다. 세션 하나는 한 프로젝트에만 있다 |
| **Ghost의 에이전트** | Ghost가 `code_run`으로 띄운 세션. 목록에 저장하지 않고, 그 맡긴 일의 프로젝트(없으면 세션 폴더를 품은 프로젝트) 아래에 그 Ghost의 얼굴과 함께 보인다. 닫힌 지 3일이 지나면 목록에서 빠진다. 열어서 지켜보거나 지시할 수 있고 「목록에 고정」하면 소유자 목록에 들어간다 |

- **새 에이전트**는 패널에서 지시를 쓰고 보내면 세션 생성·첫 지시·목록 추가가 한 번에 된다. 입력창 위에서 작업 폴더의 전체 경로를 확인하고 「폴더에서 작업」과 「별도 worktree」 중 고른다. 후보는 프로젝트 경로가 든 저장소의 최상위, 프로젝트 경로, 샌드박스, 다른 폴더다. 샌드박스에는 worktree 선택이 없고, 같은 폴더에서 다른 에이전트가 직접 작업 중이면 별도 worktree가 기본이다.
- 보내기 옆의 모델 칩은 모델과 생각 수준을 정한다. 다음 새 에이전트는 소유자가 마지막에 쓴 선택으로 시작한다. 기록이 없으면 Host 기본 모델, 그것도 없으면 처음 설정된 모델이다. 이미 시작한 세션의 모델은 변하지 않는다. Ghost가 띄운 세션은 시작값을 쓰지만 기록하지 않는다. 아래 「이어서 하기」는 이 프로젝트 목록에 없는 이전 세션이다.
- 첫 지시가 세션 이름이 된다(이름을 직접 준 세션은 제외). 샌드박스는 `~/Ghost/sandbox-<id>`의 빈 폴더에서 일하고 worktree가 없다. Ghost의 `code_run`은 여전히 저장소가 필요하다.
- **패널 분할**(넓은 화면): 에이전트를 ⌘클릭하거나 오른쪽 클릭 「옆에 열기」, 또는 목록의 에이전트를 패널 오른쪽으로 끌어 놓으면 옆에 열린다(최대 3개). 가운데에 놓으면 그 패널을 바꾼다. 경계를 끌거나 키보드 ←/→로 너비를 바꾼다. 활성 패널은 위쪽 선으로 보이고, 활성 에이전트가 Host의 포커스가 되어 휴대전화도 같은 에이전트로 돌아온다. 배치는 프로젝트마다 이 기기에 저장한다. 휴대전화는 한 번에 한 에이전트다.
- **접기**: 앱 사이드바는 제목 막대의 버튼이나 ⌘\로, 작업대의 에이전트 목록은 ⌘B로 접는다. 접힌 목록은 현재 프로젝트 에이전트의 상태 표시만 남긴 좁은 띠가 된다.
- 패널 머리는 한 줄이다: 상태, (Ghost의 에이전트면 그 얼굴) 이름(눌러서 바로 바꿈), 브랜치, 터미널, 변경, 메뉴(이름 바꾸기·맡긴 일 보기·목록에 고정·다른 프로젝트로·세션 닫기·목록에서 삭제), 패널 닫기. 모델 칩은 컴포저의 보내기 옆에 있고 맥락 사용량과 Pi 세션 설정도 그 안에 있다.
- 3일 넘게 움직이지 않은 대기 중·실패·닫힌 에이전트는 「이전 에이전트 N개」로 접힌다. 보고 있는 에이전트, 작업 중·입력 대기 에이전트, 알림 표시가 있는 에이전트는 접히지 않는다. 답변을 기다리면 목록에 질문이 먼저 보인다. 작업대 위에서 다른 프로젝트의 확인 요청도 열 수 있고, 여러 건이면 대상을 고른다. 열기만 해서는 답변하거나 재시도하지 않는다.
- **터미널**은 소유자가 터미널 버튼을 눌러야 열린다. 활성 에이전트가 일하는 폴더(없으면 프로젝트 폴더)에서 로그인 셸이 뜨고, 데스크톱에서는 패널 아래 42% 서랍으로, 휴대전화에서는 전체 화면으로 열린다. 「숨기기」는 셸을 살려 두고 다시 열면 그 셸에 붙는다(스크롤백 복원). 「종료」가 셸을 끝낸다. 터미널은 Host 재시작 뒤 남지 않고, Ghost나 에이전트가 열 수 없다. Host 상태 폴더는 막히지만 Host가 만든 worktree는 열린다.
- **코딩**은 Host가 마지막으로 본 프로젝트를 열고, 기록이 없으면 첫 프로젝트를 연다. 프로젝트 화면에서 「코딩」을 누르면 그 프로젝트의 `/coding/<scopeId>`로 바로 이동한다. 프로젝트 없음은 `/coding/-`다. 작업대 목록 머리에서 프로젝트와 설정으로 돌아갈 수 있다.
- 휴대전화에서는 에이전트 목록의 「프로젝트 목록」 버튼이 사이드바와 같은 프로젝트 목록을 연다. 에이전트를 열면 머리 한 줄에 터미널·변경·에이전트 메뉴가 있고, 아래는 컴포저가 차지한다.
- **변경**: 패널의 「변경」은 그 에이전트의 작업 변경(기준 대비)을 보여 준다. 목록 아래 「git 변경」은 프로젝트 첫 폴더를 읽는다. 파일을 누르면 그 행 바로 아래에서 스테이징된 차이와 아직 스테이징하지 않은 차이를 구별해 읽고, 다시 누르면 접는다. 파일이나 스테이징 상태는 바뀌지 않는다.
- 맡긴 일의 **코딩 세션 열기**와 응답 대기 알림은 해당 에이전트를 연다. 이미 목록에 있으면 그 프로젝트로 가고, Ghost의 세션이면 그 프로젝트에서 열며, 그 밖의 세션은 폴더를 품은 프로젝트(없으면 프로젝트 없음)에 추가한다.
- 2.41.x까지의 스페이스는 처음 읽을 때 프로젝트로 옮긴다: 같은 폴더(또는 상위 폴더)를 가진 프로젝트가 있으면 그 프로젝트로, 없고 폴더가 남아 있으면 스페이스 이름의 새 프로젝트를 만들어(구성 변경 기록이 남는다) 그리로, 폴더가 없으면 프로젝트 없음으로. 스페이스 단위 worktree는 없어지고 에이전트마다 worktree를 고른다. 2.33.x까지의 탭·패널 상태는 이전처럼 에이전트로 옮긴다.

## 구성

1. **작업대(Workbench)**: 선택한 프로젝트의 에이전트 목록, 패널 분할, 새 에이전트 시작, 완료·입력 대기 표시.
2. **Pi 설정과 확장(PiConfig)**: 자동 압축(compaction)·재시도·도구 허용 같은 Pi 설정을 전역 기본값과 세션별로 설정하고, Pi 확장·스킬·프롬프트 템플릿·패키지를 소유자가 설치·켜고 끄는 생태계 지원. 모델과 생각 수준은 설정 항목이 아니라 소유자가 마지막에 쓴 값(`pi.settings`의 `model`·`thinking`)이다.
3. **설정 › 오케스트레이션**: Ghost와 코딩 에이전트가 공유하는 에이전트 역할, 모델 역할, 동시성·깊이 한도, 대체 모델 사슬을 편집하고 전체 위임을 켜고 끈다. **설정 › 하네스 가져오기**는 같은 화면의 가져오기 패널을 연다. omp·Claude Code·Codex 설정에서 고른 항목은 저장해야 적용된다.

## 공유 규약

- 영속은 새 SQL 마이그레이션 없이 원장 설정 저장(`ledger.setting(key)`/`putSetting`)의 JSON으로 한다. 키는 갈래별 접두어(`workbench.`, `pi.`, `orchestration.`).
- API는 `/api/workbench/*`, `/api/pi/*`, `/api/orchestration/*`. 인증·오류 규약은 `/api/coding/sessions`와 같다. 작업대 API는 `GET /api/workbench`, `POST /agents {sessionId, scopeId}`, `PATCH /agents/:sessionId {scopeId}`, `DELETE /agents/:sessionId`, `POST /focus {scopeId, sessionId?}`, `GET /changes?root=[&path=]`(프로젝트 경로나 세션 폴더만), `GET /folders?scopeId=`(새 에이전트의 폴더 후보)이며 모든 쓰기는 `version`을 싣는다. 패널 배치는 기기의 `localStorage`에 둔다. 계약 타입은 `packages/ghost-contract/src/<갈래>.ts`에 둔다.
- 모든 새 도구·확장 적재는 소유자의 것이다. Ghost(비서)는 작업대를 조작하거나 확장을 설치하거나 오케스트레이션을 바꾸지 못한다(읽기 전용 조회만 허용 가능). 이를 막는 근거를 코드에 둔다.
- Host 업데이트는 작업 중이거나 답을 기다리는 내장 세션을 기다린다.
- UI는 `apps/ghost-ui/AGENTS.md`·`DESIGN.md`와 agent-ui·anti-slop 규칙을 따른다: 설명 문구 최소, 타입과 여백으로 위계. 한국어 문구.
- 확장 코드는 Host 프로세스 권한으로 실행된다. 그래서 확장 설치는 소유자 전용이고 기본은 꺼짐이며, 설치 화면에 그 사실을 한 줄로 밝힌다. 세션 하나의 확장 적재 실패는 그 세션만 막는다.

## 수용 기준

- 사이드바에서 프로젝트 작업대를 열고 지시 한 줄로 에이전트를 시작한다. 휴대전화에서는 목록 머리에서 프로젝트를 바꾼다. 넓은 화면에서 에이전트를 나란히 열고 너비를 바꾸며, 패널을 전환·분할해도 각자의 초안과 진행 상태가 남고, 새로고침·Host 재시작 뒤 프로젝트별 배치와 마지막으로 보던 에이전트가 돌아온다. Ghost가 띄운 에이전트는 맡긴 일의 프로젝트에서 그 Ghost의 얼굴과 함께 보인다. 터미널은 「터미널」 버튼을 눌러야만 열린다.
- 세션 설정에서 자동 압축을 켜고 끌 수 있고 실제 세션에 적용된다. 소유자가 설치한 Pi 확장이 세션에 적재돼 도구·명령을 더한다.
- 오케스트레이션 화면에서 역할·모델 역할·대체 사슬·한도를 그래프로 보고 편집하며, 변경이 `subagent` 도구에 즉시 반영되고, 전체를 끄면 `subagent` 도구가 사라진다. omp·Claude Code·Codex 설정에서 고른 항목을 가져올 수 있다.
