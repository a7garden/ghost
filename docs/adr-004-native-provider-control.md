# ADR-004 — bounded host-controlled native text calls

2026-10-02. Scope: two explicit in-memory configurations (OpenAI and Z.ai), a common text/usage stream, deadline/cancellation, and per-profile durable receipts. Only literal loopback fixtures were called. No credentials were fetched, no production provider was contacted, and no credential input/store or model tool registry was added.

The existing optional oxicode adapter remains. Source inspection at local oxicode checkout (`oxicode-ai/src/providers/mod.rs` and `openai.rs`, previously pinned main 5a7b8587c0bca342efd9bf1fbc62c704de5659d3) found a private shared client without host client injection; redirect/retry defaults and unbounded error-body reads cannot enforce this unit's transport policy through that adapter. Instead of modifying the SDK or rebuilding an agent SDK, add a small OpenAI-compatible **text-only** HTTP adapter behind the existing Provider trait. Rig remains a later comparison if wider engine integration needs it. The controlled interface defaults to legacy behavior, so this unit does not claim new cancellation/deadline/redaction guarantees for the optional oxicode adapter.

Production constructors require an explicit host approval for exactly one preset URL, an explicit model, and an in-memory credential object. No defaults discover credentials or load environment/config/MCP. Only `https://api.openai.com/v1/chat/completions` and `https://api.z.ai/api/paas/v4/chat/completions` are accepted. Z.ai Coding Plan endpoints are outside this unit. Endpoint/model/API compatibility and account-plan eligibility remain unverified on live APIs. The CLI does not expose native network execution or credential configuration yet.

The client disables proxies, redirects, request retries, idle reuse and fallback. Resolve the fixed approved hostname once, reject non-public addresses, and pin that checked resolution to the TLS hostname. This is a conservative address filter, not a general network sandbox. Test constructors exist only with `native-fixtures`, use literal 127.0.0.1, and cannot be deserialized or enabled in the default artifact.

The stream accepts one text choice, bounded UTF-8/multiline SSE, stop/length plus `[DONE]`, and optional finite nonnegative token counts. Function/tool calls are rejected. Limits: input 64 KiB/persona 4 KiB; default response 256 KiB, output 64 KiB, 256 frames; maximum configured response 1 MiB/output 256 KiB/1,024 frames. Default timeout is 30 s, maximum 120 s. This synchronous adapter must run outside an active Tokio runtime (e.g. a host blocking worker); nested-runtime calls fail before dispatch.

`DispatchStarted` is durably recorded before sending. After that point, connection/protocol/stream/observer failures, cancellation, timeout, redirects and server failures are `uncertain`. Cancellation before dispatch is terminal cancelled; 401/403 and 429 are definitive rejection, terminal failed. No terminal task is automatically retried. A completed model call does not authorize a filesystem action: existing host grants and effect ledger remain mandatory, and a cancellation observed before the host action stops that action. No remote rollback or exactly-once billing is claimed.

`provider_runs` and ordered normalized `provider_events` extend the existing profile DB lazily. Host-created attempt UUID correlates HTTP `X-Request-ID` with profile/session/task/message lineage. Final task/outbox/audit/receipt commit atomically. Existing interrupted-task recovery remains authoritative; a stale prepared/dispatched receipt projects canonical `uncertain` and cannot authorize resending. Received usage survives incomplete streams and is advisory reported metadata, never billing, financial authority or proof of completion. Mock/old engine tasks need no new tables.

Known credential value is removed from native request messages, model output, normalized stream and native errors, including occurrences split between text deltas. Authorization is a sensitive header. Raw provider error bodies/headers/URLs are not read into errors, DB or audit. This is exact-value redaction, not comprehensive DLP or memory zeroization; callers must not submit secrets as durable task content. Debug never exposes the credential object value. A trusted hidden input, revocable approval binding and OS credential lifecycle need their own later unit before user connection.
