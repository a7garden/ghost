# Ghost의 목표와 현재 범위

2026-11-06 사용자 결정과 현재 저장소 계약을 모은 진입점이다. 제품 목표·과업 순서·소스/설치판 인수인계의 정본이며 설치 완료 선언이 아니다. 2026-11-06에 infra `DESIGN`·`PLAN`·`HANDOFF`의 Ghost 제품 부분을 여기로 옮겼다. PC 운영·백업·복구는 [infra DESIGN](../../infra/DESIGN.md)과 [infra PLAN](../../infra/PLAN.md)을 따른다.

**일을 맡기면 대화와 책임이 유지되고, 필요한 협업을 거쳐 확인 가능한 결과로 돌아온다.** 사용자는 담당자를 중계하거나 내부 실행기를 관리할 필요가 없다. 기본 Ghost에게 시작하거나 원하는 Ghost에게 직접 맡긴다. 모든 Ghost는 같은 종류의 지속형 Pi Durable 봇이며 기본 역할이 별도 실행 계층을 만들지 않는다.

모델은 등록된 외부 제공자로 실행할 수 있다. 소유자 결정으로 로컬 모델 사용과 복구는 최소 Ghost의 완료 조건에서 제외한다. 외부 모델을 쓰는 대화와 업무는 해당 제공자에 허용된 자료 범위를 따른다.

## 핵심 사용자 흐름

1. 대화에서 일을 맡기고 목표·제약·완료 조건을 확인한다. 일반 대화나 아이디어를 자동으로 과업으로 만들지 않는다.
2. 담당 Ghost가 직접 처리하거나 다른 Ghost에게 위임한다. 같은 책임의 진행·막힘·사용자 결정 대기를 추적한다.
3. 사용자는 **맡긴 일**에서 상태와 결과를 확인하고 수정·취소·재개한다. 기존 Goal/Work가 정본이며 별도 개인 할 일 원장을 만들지 않는다.
4. 산출물과 실제 효과를 검수한 뒤 완료를 보고한다. 실행 종료·파일 생성·모델의 완료 주장만으로 수용하지 않는다.
5. 앱 종료나 연결 끊김 이후에도 같은 대화·과업으로 돌아온다. 효과가 불명확하면 대사 후 재개하며 중복 실행하지 않는다.

기존 Goal/Work와 Host 권한·효과 대사·수용을 재사용한다. `deadline_ms`는 실행 예산이다. 사용자 마감일 기능을 새로 요구하지 않는다.

## 책임 경계

| 구성 | 책임과 정본 |
| --- | --- |
| Ghost | 동등한 지속형 봇. 각자의 정체성·권한·기억 범위와 Pi Durable 대화/실행 |
| 기본 Ghost | 기본 진입점과 조율 역할. 다른 Ghost와 동일한 실행·복구 능력 |
| Host | 등록·권한·Goal/Work·위임·효과 영수증·검수·수용, 상태 루트의 단일 writer |
| Pi Durable | 담당 Ghost의 대화·task·도구 실행·checkpoint. 별도 OMP/LLM executor를 새로 두지 않음 |
| Oxibrain | 출처·범위·정정을 가진 기억. Host 업무 원장이나 사용자 원문을 대체하지 않음 |
| 문서 평면 | 소유 프로젝트의 PDC 2 계약. Markdown/HTML 정본과 PDC 1 읽기 호환, 승인 없는 일괄 변환 금지 |
| Dyno 및 모델 소비자 | 실제 소유 경계와 자원 계약을 따른 모델 수명·라우팅. 모든 소비자를 임의로 중앙화하지 않음 |
| infra | 프로젝트 간 운영·복구·자원 조정과 근거 기록 |

구현 세부는 [Pi 직접 실행](pi-direct-execution.md)과 [저장소 지침](../AGENTS.md)을 따른다. 구형 OMP 기록의 조회·정리·영수증·산출물 호환과 신규 OMP 실행은 구분한다.

## 접점

- Mac과 네이티브 iPhone에서 같은 Ghost·대화·과업에 접근한다. iPhone의 대화·위임·승인·결과·재연결에는 외부 메신저가 필요하지 않다. 기기 grant는 명시된 Ghost/대화 범위에 한정한다.
- 현재 운영 기준은 Studio의 단일 Host와 외부 Host 모드 Mac 앱이다. Gateway와 로컬 추론은 같은 Host에 연결한다. [설치판 확인과 복구](local-operations.md)
- mini는 Studio가 꺼져도 이어지는 상시 운영의 후속 목표다. 현재 writer를 이미 mini로 옮겼다고 설명하지 않는다. 인수·펜스·재부팅·복구를 검증한 별도 전환으로 다룬다.
- 음성, 닫힌 앱 알림과 장기 사용 수용은 남아 있는 후속 범위다. 텍스트로 일을 맡기고 결과를 회수하는 현재 흐름의 선행 대공사로 묶지 않는다.

## 완료를 판단하는 기준

소스/자동 시험, 설치판, 실물 기기, 운영 복구 증거를 분리한다. 현행 판본에서 요청→실행/위임→결정 대기→결과 검수→동일 대화 보고를 실제로 확인하고 실패·취소·재접속 때 중복 효과가 없는지 확인한다. 이전 성공을 새 릴리스의 성공으로 자동 승계하지 않는다. 소스 시험이나 fixture 성공은 설치판과 실물 기기 수용을 대신하지 않는다.

10월의 제품·E2E·W00–W12 문서는 [역사 자료](../../infra/reports/2026-11-05/previous-docs/DESIGN.md)다. 이전의 전체 기능 목록을 현재 출시 체크리스트로 사용하지 않는다.

## 소스와 설치판 인수인계

기준: 2026-11-05. 개인 캘린더를 복구하거나 OMP 실행기로 전환하는 작업에서 시작하지 않는다.

- 정본 로컬·원격 `main`에서 확인한 기준은 `6317557`이다. 과업 전용 탐색·planner 제거, Bun/Pi CodingTools, 협업 관계 화면(`55e919c`)과 지속 과업 스레드(`6559c29`), 문서 작성/검토 화면(`3e6fc8b`)과 목표 진입 문서(`6317557`)가 통합돼 있다. 이후 커밋은 작업 시작 시 다시 확인한다.
- Studio 설치 링크는 `20261104-dashboard-4a6b57a`다. 운영 `com.a7.ghost`, 외부 Host Mac 콘솔과 Gateway listener를 읽기 전용으로 재확인했다. 구형 worker LaunchAgent 네 개와 `com.a7.ghost-ui`는 disabled다. `5178`에는 별도 개발 `npm run dev`가 있어 다른 작업의 서버로 보존했다.
- Gateway 비인증 `/health`는 403이었다. listener 확인을 인증된 연결·기능 수용으로 확대하지 않는다.
- 실제 iPhone 개발 서명 설치와 실행은 기록돼 있지만 현재판 대화 조회·전송·승인·결과·재연결 왕복은 별도 확인이 필요하다. [설치 및 복구 기록](local-operations.md)

과업 전용 UI 통합 `aaf0ee8`에서 UI 시험 268개, bridge/package 17개, build, 브라우저 78개 점검이 통과했고 page error는 없었다. 브라우저 검증은 fixture다. 증거는 `.orch/ghost-task-only-integration/`에 있다. 오프라인 새 의존성 설치는 tarball cache 부족으로 실패했고 기존 개발 의존성으로 검증했다.

운영 재시작은 하위 Ghost의 실행·산출물 검수와 기본 Ghost의 중간 보고까지 확인한 기록이며 최종 수용/보고는 미확인이다. 이후 격리 Bun 경로 시험과 혼합해 운영 전체 성공으로 쓰지 않는다. [정리 전 운영 근거](../../infra/reports/2026-11-05/previous-docs/SYSTEM.md)

이어갈 작업:

1. 통합된 협업 화면·과업 스레드의 검증 결과를 설치 후보에 연결한다. 추가 UI와 실행 도구 변경은 다른 채팅의 소유 범위이므로 덮어쓰지 않는다.
2. 같은 릴리스 후보에서 Mac/iPhone 수용과 복구·최종 보고를 확인한다. 설치·운영 변경은 해당 승인 범위와 복귀 자료를 확인한 뒤 진행한다.

A04 실패, 기기/권한 제한은 새 문서를 썼다고 해제되지 않는다. 예전 “최신” 항목이 현재 설치판을 설명한다고 가정하지 않는다. 기존 Primary의 Codex 전용 대화 이력을 ZAI로 처리할지에 관한 과거 질문은 승인 근거가 확인되지 않았다. 새 제공자로 기존 이력을 처리하기 전 현재 grant와 소유자 결정을 확인한다. [정리 전 인수인계](../../infra/reports/2026-11-05/previous-docs/HANDOFF.md)

런타임 구현은 [Pi 직접 실행](pi-direct-execution.md), 상태 루트·실행판·복귀는 [로컬 운영](local-operations.md), 제품 원칙은 [AGENTS](../AGENTS.md)를 따른다. 날짜별 문서의 이전 단계 전체를 새 backlog로 가져오지 않는다.
