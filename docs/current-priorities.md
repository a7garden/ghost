# Ghost의 목표와 현재 범위

2026-11-06 사용자 결정과 현재 저장소 계약을 모은 진입점이다.

**일을 맡기면 대화와 책임이 유지되고, 필요한 협업을 거쳐 확인 가능한 결과로 돌아온다.** 기본 Ghost에게 시작하거나 원하는 Ghost에게 직접 맡긴다. 모든 Ghost는 같은 종류의 지속형 Pi Durable 봇이며 기본 역할이 별도 실행 계층을 만들지 않는다.

## 핵심 흐름

대화에서 목표와 완료 조건을 확인하고 담당 Ghost가 직접 실행하거나 위임한다. 사용자는 **맡긴 일**에서 진행·막힘·결정 대기·결과를 확인하고 수정·취소·재개한다. 검수된 결과가 같은 대화로 돌아오고 앱 종료·연결 끊김 뒤에도 같은 과업을 이어간다.

기존 Goal/Work와 Host 권한·효과 대사·수용을 재사용한다. `deadline_ms`는 실행 예산이다. 사용자 마감일 기능을 새로 요구하지 않는다.

모델은 등록된 외부 제공자로 실행할 수 있다. 소유자 결정으로 로컬 모델 사용과 복구는 최소 Ghost의 완료 조건에서 제외한다. 외부 모델을 쓰는 대화와 업무는 해당 제공자에 허용된 자료 범위를 따른다.

## 범위

- 유지: 과업 관리, Ghost 간 협업, 지속 실행·복구, 요청한 후속 대응·완료 알림, 네이티브 Mac/iPhone 접점.
- 제외: 개인 캘린더, 별도 개인 할 일 앱, Google Calendar/Tasks·CalDAV 전용 planner, 캘린더 기반 기본 briefing, 신규 OMP/별도 LLM 작업자 계층.
- 보존: 기존 원본·자격·구형 API·영수증·산출물과 범용 연동. 호환 코드가 있다는 이유로 현재 제품 기능이나 출시 필수 조건으로 세지 않는다.

## 다음 수용

최신 과업·협업 소스를 같은 릴리스 후보로 고정하고, 설치판 Mac 흐름·실물 iPhone 요청/승인/결과/재연결·실행 중 복구와 최종 보고를 확인한다. 소스 시험이나 fixture 성공은 설치판과 실물 기기 수용을 대신하지 않는다. mini 인수, 음성/APNs, 기억·문서·봇 생성의 남은 시나리오는 각각 후속 근거와 범위를 정한다.

현재 과업과 설치판 차이는 [infra PLAN](../../infra/PLAN.md)·[HANDOFF](../../infra/HANDOFF.md)에 모은다. 런타임 구현은 [Pi 직접 실행](pi-direct-execution.md), 상태 루트·실행판·복귀는 [로컬 운영](local-operations.md), 제품 원칙은 [AGENTS](../AGENTS.md)를 따른다. 날짜별 문서의 이전 단계 전체를 새 backlog로 가져오지 않는다.
