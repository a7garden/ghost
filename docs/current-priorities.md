# Ghost의 목표와 현재 범위

제품 목표와 과업 순서의 정본이다. 구조는 [architecture](architecture.md), 운영은 [local-operations](local-operations.md)를 따른다.

**일을 맡기면 대화와 책임이 유지되고, 필요한 협업을 거쳐 확인 가능한 결과로 돌아온다.** 사용자는 담당자를 중계하거나 내부 실행기를 관리하지 않는다. 기본 Ghost에게 시작하거나 원하는 Ghost에게 직접 맡긴다. 모든 Ghost는 같은 종류의 지속형 봇이며 도구 권한은 각자 설정한다. 메인 Ghost만 직접 대화에서 Ghost를 새로 만들고 다른 Ghost의 설정을 바꿀 수 있고, 메인 지정과 자기 자신의 도구·실행 권한 변경은 소유자에게 남는다.

모델은 등록된 외부 제공자로 실행한다. 로컬 모델은 고려하지 않는다. 대화별 개인정보 등급은 없고, 자격이 있는 제공자는 모든 대화와 Ghost의 모든 도구를 쓴다(2026-11-07 소유자 결정).

## 방향 조정 (2026-11-21)

Ghost는 소유자의 **바깥 루프**다. 맥락을 모으고, 일을 맡기고, 증거를 회수하고, 결정 대기열을 관리한다. 저장소 코드의 실행은 코딩 에이전트(`code_run`)와 도구가 한다. 이 조정의 근거는 [패러다임](ghost-paradigm.md)의 관측(하위 맡긴 일 완료율 29%, 목표·프로젝트 사용 0, 승인 응답 중앙값 10초)과 외부 사례(읽기 전용 봇에서 시작해 신뢰를 쌓고, 사람은 diff가 아니라 실행 증거를 본다)다. 소유자 지시로 적용한다.

- **한 줄기를 먼저 완주시킨다.** 새 기본 요소를 더하기 전에 프로젝트 하나에서 계기, 맡긴 일, `code_run`, 실행 증거, 소유자의 결과 확인이 끝까지 도는지 보고 수용률을 잰다.
- **스스로 판단한 일은 관찰·조사·초안·제안까지다.** `initiative` 맡긴 일은 소유자의 PC(`execution.kind: host`)를 받지 못한다(Host가 거절). 소유자의 저장소나 Mac을 바꿀 일은 근거와 함께 제안하고 소유자가 맡길 때 시작한다. 2026-11-10의 "스스로 일한다" 결정 중 자율 실행의 범위를 좁힌 것이다. 수용률이 쌓이면 범위를 다시 연다.
- **완료는 실행 증거로 판정한다.** 코드·UI 맡긴 일은 시작 때 목표와 가장 작은 변경을 재진술하고, 끝낼 때 실행 출력이나 스크린샷을 산출물로 낸다. 검토 대화는 완료 기준과 소유자의 지키는 선으로만 판정하고, 요청보다 쉬운 것을 냈는지 본다.
- **목표·이정표는 검토일이 있다.** 코드는 유지하되 2026-12-21까지 소유자가 목표를 등록해 쓰지 않으면 코드와 화면을 제거 대상으로 올린다.
- **담당과 평가의 모델 등급은 설정의 일이다.** 구조 변경의 효과를 재려면 담당과 평가를 가장 강한 등록 모델로 올려야 한다(소유자 설정, 코드 변경 없음).

## 핵심 사용자 흐름

1. 대화에서 일을 맡기고 내용·완료 기준을 확인한다. 일반 대화나 아이디어를 자동으로 맡긴 일로 만들지 않는다. Ghost가 스스로 판단해 시작한 일은 `initiative`로 표시되고 소유자 대신 Ghost가 검토하며, 소유자의 PC는 받지 못한다.
2. 담당 Ghost가 직접 처리하거나 다른 Ghost에게 위임한다(하위 맡긴 일). 팀원끼리도 메인을 거치지 않고 일을 의뢰하며, 같은 과업의 팀원에게 필요한 사실을 직접 묻고 답한다. 일의 책임·수용은 트리로 유지하고 질문만 필요한 상대에게 연결한다. 진행·대기·막힘·결정 대기를 추적한다.
3. 사용자는 **맡긴 일**에서 상태와 결과를 확인하고 수정·취소·재개한다.
4. 산출물은 확인 규칙, 검토자, 또는 사용자 수용으로 판정한다. 완료 주장만으로 수용하지 않는다.
5. 앱 종료·Host 재시작 뒤에도 같은 대화·맡긴 일로 돌아온다. 결과가 불명확한 효과는 사용자가 대사한 뒤 이어가며 다시 실행하지 않는다.
6. Ghost는 **스스로 일한다**(2026-11-10 소유자 결정). 각 Ghost가 다음에 언제 무엇을 볼지 직접 정하고(`plan_next`), Host는 그 시각이나 지켜보는 프로젝트의 새 커밋에 맞춰 깨운다. 메인은 팀원의 계획을 보고 일을 맡기거나 다음 시각을 잡아 준다. 소유자는 Ghost 설정에서 끌 수 있다. 하루·동시 실행 한도가 비용을 묶는다.
7. Ghost별 **자동 활동**을 승인하면 예약·PR·메일 변화를 Host가 감지해 같은 맡긴 일 경로로 실행한다. 도구·실행 환경·일일/동시 한도·다음 점검·답글 정책을 정하고, 실행 기록에서 멈추거나 다시 설정한다.
8. 팀은 **일에서 자란다**(2026-11-10 소유자 결정). 처음엔 메인 하나와 대화하다가, 반복되는 일이 전담 역할을 원하면 메인이 Ghost를 만들고(`ghost_create`), 결과가 같은 식으로 어긋나면 그 Ghost의 페르소나·메모·도구를 고친다. 각 Ghost는 이 환경에서 통하는 방법을 페르소나와 별도로 적어 두고(`self_adapt`) 다음부터 거기서 시작한다. 없는 도구나 PC 실행이 필요하면 실패하는 대신 요청하고(`capability_request`), 메인이나 소유자가 허용하면 바로 이어간다. Mac을 여는 권한은 시간이 지나도 자동 허용되지 않는다.
9. 메인은 **팀을 연결한다**(2026-11-10 소유자 결정). 일반 맡긴 일의 결과·실패·막힘을 받아 목표와 다음 행동을 연결하고, 팀 전체의 진행을 살펴 살아 있는 일의 방향을 바로잡는다. 모든 메시지의 중계자나 모든 과업의 필수 실행자는 아니다. 이미 취소된 일을 다시 시작하거나 마감·수용 조건·권한·자동 활동 규칙을 임의로 바꾸지 않는다. [협업 구조와 조사 근거](architecture.md#collaboration-structure-and-research).
10. 팀은 **먼 목표를 향한다**(2026-11-11 소유자 결정, 2026-11-12 프로젝트별로 확장). 목표는 오래 향할 방향이지 마감·목표치가 아니며 어떤 권한도 주지 않는다. 팀 전체의 목표이거나 한 프로젝트의 목표이고, 열린 목표는 팀과 프로젝트마다 3개까지다(프로젝트 한도로 조정). 소유자가 직접 적거나, 메인이 제안(`goal_propose`)하면 소유자만 등록한다. 목표 아래에는 메인이 가까운 이정표만 세우고(예정 4개, 진행 중 2개까지), 이정표는 연결된 맡긴 일이 수용돼야 완료되며 접은 이정표는 이유를 남긴다. 목표와 지키는 선은 모든 자율 깨우기와 연결된 맡긴 일에 함께 들어간다. **목표** 화면은 프로젝트별로 묶어 보이고, 각 프로젝트 화면의 「목표」 탭에는 그 프로젝트의 목표가 있다. 이정표는 시간 순서의 한 줄로 쌓인다. [팀 목표](architecture.md#team-goals).
11. 일은 **프로젝트**에 속할 수 있다(2026-11-12 소유자 결정: 조직과 내부 구조는 코드로 고정하지 않고 사용자가 꾸린다). 프로젝트(Scope)가 맡긴 일·결정·목표·자동 활동·승인 규칙·성과와 비용이 귀속되는 단위다. 사용자는 대화와 맡긴 일에 `#프로젝트`를 붙인다. 프로젝트 화면은 받을 Ghost가 있으면 대화로 열리고, 매일 쓰는 탭은 대화·맡긴 일·문서·목표 넷이다(맡긴 일 위에 이 프로젝트의 확인할 일이 먼저 온다). 자동 활동·승인 규칙·성과와 비용·변경 기록은 「설정」 안에 있다(2026-11-24 재설계, [프로젝트 설계](project-design.md)). 프로젝트에 속하지 않는 일과 목표도 그대로 둔다. 프로젝트마다 담당 Ghost를 두는 담당제와 역할 플레이북은 코드가 강제하지 않는 [권장 구성](ghost-paradigm.md)이다. [기반 설계](ghost-infrastructure.md).

| 프로젝트(Scope) | 경로·문서 금고·맥락 문서·받을 Ghost(선택)·상태·한도의 묶음. 맡긴 일·결정·목표·자동 활동·승인 규칙·성과와 비용·변경 기록이 귀속된다. 프로젝트 자체는 PC 권한을 주지 않는다 |
| 문서 평면 | PDC 2 금고(프로젝트에 붙는 문서 Space). PDC 1 읽기 호환, 승인 없는 일괄 변환 금지 ([PDC 채택](pdc-adoption.md)) |
| infra | 프로젝트 간 운영·복구·자원 조정 |

## 접점

- Mac 앱과 웹 UI는 Host가 직접 제공한다. iPhone은 같은 웹 UI를 페어링한 기기 토큰으로 그대로 사용하며 소유자와 동등한 권한을 가진다(2026-11-09 소유자 결정). 기기 관리만 소유자 영역이다: 페어링 시작·기기 이름 변경·다른 기기 해제는 소유자만, 기기 자신의 해제는 가능하다.
- 음성 통화는 [전화 설계](voice-calls.md)대로 앱 안에서 쓸 수 있다(소유자 결정 2026-11-23, Host 2.27.0). 전화망 발신(전화 대행)은 보류다. 닫힌 앱의 승인 요청·맡긴 일 완료 알림은 아래 iPhone 푸시 알림 기준으로 실물 수용한다.
- 브라우저의 로그인·CAPTCHA·2FA는 같은 세션의 소유자 화면이나 실제 Mac 창으로 인계한다. 로그인은 금고에 저장하고, 이름·전화·주소·카드는 허용한 Ghost가 사용한다. 메일 화면은 등록한 IMAP/SMTP 계정을 한 곳에서 읽고 쓰는 클라이언트다(계정이 둘 이상이면 전체 받은편지함, 새 메일 자동 갱신과 도착 알림). Ghost의 메일 도구와 발송은 별도 허용·승인을 받는다. Mac 문자 코드는 도구 권한·전체 디스크 접근·iPhone 문자 전달이 필요하다.

| 자동 활동·연결·PC 실행 | 서비스 목록에서 계정을 고르고 메일 서버는 자동 설정한다. OAuth 앱 등록이 필요한 서비스는 선행 조건을 표시하며, Ghost가 키 발급·보안 등록을 도울 수 있다. API 계정 접근은 Ghost별로 허용하고 외부 쓰기는 별도 확인한다. PC는 격리나 승인 방화벽이 아니며 파일·명령에 OS 사용자 권한이 적용된다. 컨테이너는 Work별 필요할 때만 생성하고 PC로 자동 대체하지 않는다. PR·메일 답글 정책은 브라우저·셸까지 통제하지 않는다. 검증·설치 증거는 [로컬 운영](local-operations.md)에 기록한다. |

소스 시험이나 임시 루트의 실제 모델 시험은 설치판과 실물 기기 수용을 대신하지 않는다.
