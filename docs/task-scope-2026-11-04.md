# Ghost 과업 관리 범위 — 2026-11-04

2026-11-06 infra `plans/2026-11-04-ghost-task-scope.md`에서 옮겼다. 내용은 원본 그대로다.

사용자 확정: 현재 캘린더는 필요하지 않다. 과업 관리는 유지하고 불필요한 기능과 설계 요구를 덜어낸다. 이 결정은 이전 Google 개인 planner·일정 정본 선택과 관련 구현/출시 조건을 대체한다.

## 유지할 제품 기능

- 대화에서 실제로 맡긴 과업의 목표·완료 조건·담당·현재 상태·결과를 같은 Goal/Work로 추적한다. 아이디어나 일반 대화를 자동으로 과업으로 만들지 않는다.
- 진행 중·사용자 응답 대기·막힘·완료를 구분하고 수정·취소·재개와 결과 확인을 제공한다. 기존 과업 화면과 장부를 재사용한다.
- 과업 실행의 시간 제한과 요청한 재개·후속 보고 경로를 유지한다. 사용자 마감일은 현재 Work의 실행 제한시간과 다르며 이번 변경에서 별도 마감일 기능을 추가하지 않는다. Host의 지속 실행·wake·재시작 복구·중복 방지·완료 알림은 유지한다.
- 과업 현황은 요청 시 조회하며 중요한 막힘·결정 요청·결과를 알린다. 정기 요약은 사용자가 요청한 책임에만 연결한다.

## 현재 제품과 설계에서 제외

- 개인 캘린더, 일간·주간·월간 일정 화면, 약속·초대·반복 일정 편집.
- 과업 장부와 별개인 개인 할 일 목록 및 이를 위한 독립 planner 화면.
- Google Calendar/Tasks·CalDAV의 전용 설정 프리셋, 동기화·이관·정본 전환 작업과 해당 OAuth·원격 ID·중복 일정 수용 조건.
- 캘린더 조회를 전제한 아침 briefing, 음성 시연, 외부 업무 결과의 자동 Calendar 등록.

별도 개인 할 일 앱이나 외부 할 일 서비스 연동을 과업 관리의 선행 조건으로 두지 않는다. 외부 업무의 결과·효과 확인은 해당 서비스의 실제 영수증으로 검증한다.

## 보존과 구현 경계

기존 일정·할 일·연동 원본과 자격을 삭제하거나 자동 변환하지 않는다. 보존용 schema·구형 API·명령 영수증이 남아 있어도 현재 제품 기능이나 출시 필수 조건으로 세지 않는다. 기존 범용 연동과 사용자가 등록한 설정은 일괄 철회하지 않는다. 구형 fixture 대화의 planner 도구 카탈로그도 호환 경로로 보존하지만 정본 Pi 대화에 새로 노출하지 않는다. 과거 실험·실패·검증 보고는 역사로 보존한다.

제품 탐색·검색·설정에서 개인 planner를 제거하고 이전 planner 링크는 기존 과업 화면으로 연결한다. 설치판 반영 여부는 소스 변경과 구분해 기록한다. 런타임 내부의 과업 스케줄러나 시스템 백업 예약을 개인 캘린더와 혼동해 제거하지 않는다.

## 수용 기준

1. 탐색·검색·설정 프리셋·직접 URL에서 개인 캘린더/planner 화면을 새로 열지 않는다.
2. 기존 과업의 상태·수정·취소·결과 확인 경로와 요청한 시점의 후속 대응이 유지된다.
3. 제품 계약·구현 순서·G05/G06·W09·출시 조건에 Google planner 연결이 필수로 남지 않는다.
4. 데이터 삭제·마이그레이션·자격 철회·새 일정 생성 없이 검증한다.

캘린더 재도입은 실제 반복 수요와 별도 사용자 결정이 있을 때 다시 평가한다. 미완료 backlog로 자동 복구하지 않는다.
