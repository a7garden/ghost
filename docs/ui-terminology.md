# Ghost UI 용어

React UI의 메뉴, 제목, 버튼, 상태 안내와 접근성 이름에 적용한다.
공통 이름은 `apps/ghost-ui/src/uiText.ts`에서 가져온다.
사용자가 작성한 역할 지시·대화·문서, 모델 응답, 인용문, API 식별자는 이 기준으로 바꾸지 않는다.

| 개념 | UI 표기 | 사용 범위 |
| --- | --- | --- |
| Workspace | 작업실 | Ghost, 대화, 작업과 문서 공간을 모아 보는 곳 |
| Inbox | 확인할 일 | 문서 검토, 실패, 결과 미확정, 사용자 확인 대기와 작업 결과 |
| Work 화면 | 맡긴 일 | 사용자가 Ghost에게 맡긴 일을 모아 보는 화면 |
| 개별 실행·Task | 작업 | 대화 응답 생성, 도구 실행과 실행 결과 |
| Goal | 목표 | 작업이 충족해야 할 요구사항과 완료 기준 |
| Collaboration | 협업 | Ghost 사이의 요청, 참여와 결과 전달 |
| Delegation | 위임 | 한 Ghost가 다른 Ghost에게 작업을 맡기는 구체적 동작과 권한 |
| Schedule | 반복 작업 | 지정한 간격으로 실행하는 작업. 만드는 동작은 ‘반복 작업 예약’ |
| Review | 문서 검토 | 저장 전 내용을 확인하는 절차. 여는 버튼은 ‘검토하기’ |
| Approval | 승인 | 검토 후 허용하는 결정. 저장과 구분하고 대기·실패 상태를 유지 |
| History | 대화 기록 / 작업 기록 / 실행 기록 | 대상에 맞게 구분. ‘이력’과 번갈아 쓰지 않음 |
| Persona | 역할 지시 | 모델에 적용하는 지시 원문. 짧은 소개는 원문의 발췌 |
| Avatar | 아바타 | Ghost를 나타내는 이미지·캐릭터 |
| Pet | 펫 | 작업실에 따로 표시하는 움직이는 캐릭터. 아바타와 구분 |
| Host | 호스트 | Ghost의 실행과 저장을 관리하는 로컬 서버 |
| Receipt | 접수 기록 | 요청의 접수·처리 상태를 확인하는 기록. 작업 완료 근거와 구분 |
| Artifact | 첨부 자료 / 결과 자료 | 대화에 붙일 때는 첨부 자료, 작업 산출물을 보여 줄 때는 결과 자료 |
| Demo / fixture UI | 예시 모드 | 실제 호스트나 외부 도구를 실행하지 않는 화면 예시 |

## 문구 기준

- 같은 대상과 동작에는 같은 이름을 쓴다. 메뉴·제목·검색·접근성 이름을 함께 맞춘다.
- 버튼은 ‘일 맡기기’, ‘검토하기’, ‘결과 확인’, ‘일시정지’, ‘재개’처럼 실제 동작을 쓴다.
- 상태는 ‘진행 중’, ‘확인 필요’, ‘대기 중’, ‘완료’, ‘실패’, ‘취소됨’으로 표시한다. 구체적인 응답·협업·저장 상태는 별도로 명시한다.
- 설명은 ‘…합니다’, 안내는 ‘…해 주세요’로 쓴다. 짧은 빈 상태에는 ‘…없음’을 쓴다.
- 오류 안내는 확인된 결과와 가능한 다음 동작을 말한다. 원인·재시도 성공·완료를 추정하지 않는다.
- 목표와 작업, 검토와 승인, 저장과 검수, 응답 취소와 작업 취소를 합쳐 표현하지 않는다.
- 제품명, 명령·필드·권한 식별자, URL, 수치·단위는 유지한다. 기술 식별자는 필요한 상세 정보에서 보여 준다.

이 기준은 anti-slop의 D25(용어와 동작 일관성), W12/W29(구체적인 표현), W21(의미 보존)을 따른다.
