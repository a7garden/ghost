# Ghost UI 용어

React UI의 메뉴, 제목, 버튼, 상태 안내와 접근성 이름에 적용한다.
공통 이름은 `apps/ghost-ui/src/uiText.ts`에서 가져온다.
사용자가 작성한 역할 지시·대화·문서, 모델 응답, 인용문, API 식별자는 이 기준으로 바꾸지 않는다.

| 개념 | UI 표기 | 사용 범위 |
| --- | --- | --- |
| Workspace | 작업실 | Ghost, 대화, 작업과 프로젝트를 모아 보는 곳 |
| Scope | 프로젝트 | 경로·문서 금고·맥락 문서·받을 Ghost·한도를 묶고 맡긴 일·결정·목표·자동 활동이 귀속되는 단위. ‘Scope’, ‘Space’, ‘공간’은 UI에 쓰지 않음. 프로젝트에 속하지 않은 일과 목표는 ‘전체’로 표시 |
| Workbench space | 스페이스 | 코딩 작업대에서 저장소나 폴더 하나에 묶은 작업 공간. 프로젝트와 별개 |
| Coding agent | 에이전트 | 스페이스에 나열된 내장 코딩 세션. 닫아도 세션은 남음. 작업대에는 ‘탭’, ‘패널’, ‘분할’이 없음. 터미널은 헤더 「터미널」로 여는 보조 서랍 |
| Project tabs | 대화 / 맡긴 일 / 문서 / 목표 / 설정 | 프로젝트 화면의 갈래. 맡긴 일 위에는 그 프로젝트의 ‘확인할 일’이 먼저 온다. 설정은 기본 정보 / 자동 활동 / 승인 규칙 / 성과와 비용 / 변경 기록. ‘자동 활동’은 예약·커밋처럼 일을 시작시키는 조건, ‘승인 규칙’은 허용·거절·검토 정책, ‘성과와 비용’은 완료율·반려율·비용 집계, ‘변경 기록’은 설정 변경 이력. ‘계기’·‘규칙’·‘계측’·‘구성 기록’·‘결정’ 탭 이름은 쓰지 않음 |
| Inbox | 확인할 일 | 문서 검토, 실패, 결과 미확정, 사용자 확인 대기와 작업 결과 |
| Work 화면 | 맡긴 일 | 사용자가 Ghost에게 맡긴 일을 모아 보는 화면 |
| 개별 실행·Task | 작업 | 대화 응답 생성, 도구 실행과 실행 결과 |
| Goal | 목표 | 팀 전체 또는 한 프로젝트가 오래 향하는 방향. 마감이나 목표치가 아니며, 맡긴 일의 완료 기준과 구분. 목표 화면은 프로젝트별로 묶고, 프로젝트 안에서는 ‘목표’ 탭 |
| Milestone | 이정표 | 목표 아래의 한 단계. 상태는 ‘예정’, ‘진행 중’, ‘완료’, ‘접음’ |
| Acceptance criteria | 완료 기준 | 맡긴 일이 충족해야 할 요구사항과 판정 조건 |
| Collaboration | 협업 | Ghost 사이의 요청, 참여와 결과 전달 |
| Delegation | 위임 | 한 Ghost가 다른 Ghost에게 작업을 맡기는 구체적 동작과 권한 |
| Schedule | 반복 작업 | 지정한 간격으로 실행하는 작업. 만드는 동작은 ‘반복 작업 예약’ |
| Review | 문서 검토 | 저장 전 내용을 확인하는 절차. 여는 버튼은 ‘검토하기’ |
| Approval | 승인 | 검토 후 허용하는 결정. 저장과 구분하고 대기·실패 상태를 유지 |
| History | 대화 기록 / 작업 기록 / 실행 기록 | 대상에 맞게 구분. ‘이력’과 번갈아 쓰지 않음 |
| Persona | 페르소나 | Ghost가 누구이고 어떻게 일하는가: 말투, 좋은 결과의 기준, 혼자 정할 것과 물을 것(필드 `persona`). 첫 줄은 목록의 한 줄 소개. 작품·저장소의 사실은 프로젝트 자료, 이 Mac의 방법은 환경 적응, 일회성 역할 절차는 스킬에 둔다([제품 개념](concept.md)). ‘책임과 원칙’은 쓰지 않음 |
| Agent settings | Ghost 설정 | 팀 목록·대화 프로필에서 여는 페르소나·모델·도구 권한 편집. 페르소나가 맨 위 |
| Tool permissions | 도구 권한 | 고스트별 선택 도구. 대화 종류·문서 권한 제한을 우회하지 않음 |
| Settings navigation | Ghost와 일 / 연결과 기기 / 앱 / 고급 | 설정 왼쪽 목록의 묶음. 날마다 쓰는 설정은 앞의 셋에 있고, 사람이 매일 이해할 필요가 없는 기계적인 설정은 접힌 ‘고급’ 아래 한 곳에 둔다. 새 설정은 사람이 읽고 고를 수 있어야 앞의 묶음에 들어가고, 식별자·패턴·JSON을 다뤄야 하면 ‘고급’에 넣는다 |
| Policy rule | 승인 규칙 | 고급. 규칙마다 한 문장(‘행동 · 조건 → 처리’)으로 쓴다. 처리는 ‘바로 진행 / 내가 확인 / 검토 후 진행 / 막기’. 처음부터 있는 규칙은 ‘기본 안전 규칙’으로 접는다. ‘정책 규칙’, ‘도구 무늬’, ‘대상 ID 무늬’, ‘개정’은 쓰지 않음 |
| Config revision | 변경 기록 | 고급. ‘내가 프로젝트를 만들었습니다’ 같은 문장과 바뀐 항목. ‘구성 기록’, 식별자(`scope.create`), JSON은 기본 화면에 쓰지 않고 ‘기술 정보’에만 둔다 |
| Model slot | 모델 조합 | 고급. 모델 하나와 이어받을 모델들의 묶음에 붙인 이름. ‘모델 자리’, ‘슬롯’은 쓰지 않음 |
| Limits | 작업량 한도 | 고급. 하루에 스스로 시작하는 횟수·한 번에 만들 수 있는 일의 수처럼 무엇을 얼마나 막는지 일상어로 쓴다. ‘깨움’, ‘트리 크기’, ‘노드’는 쓰지 않음 |
| MCP server | 외부 도구 서버 | 고급. 설명에서만 ‘MCP’를 밝힌다 |
| Host connection | 연결 상태 | 설정의 앱 묶음. 연결·대화 실행 가능 여부·버전·다시 연결 |
| Avatar | 아바타 | Ghost를 나타내는 이미지·캐릭터 |
| Pet | 펫 | 작업실에 따로 표시하는 움직이는 캐릭터. 아바타와 구분 |
| Host | 호스트 | Ghost의 실행과 저장을 관리하는 로컬 서버 |
| Connection state | 연결됨 / 연결 확인 중 / 재연결 중… / 연결 끊김 / 연결 필요 | 호스트 이벤트 스트림 상태. 첫 접속은 연결 확인 중, 끊긴 뒤 다시 붙는 동안은 재연결 중…, 오래 실패하면 연결 끊김, 받은 데이터가 없으면 연결 필요. 다시 시도하는 버튼은 ‘다시 연결’. ‘갱신 지연’은 쓰지 않음 |
| Receipt | 접수 기록 | 요청의 접수·처리 상태를 확인하는 기록. 작업 완료 근거와 구분 |
| Artifact | 첨부 자료 / 결과 자료 | 대화에 붙일 때는 첨부 자료, 작업 산출물을 보여 줄 때는 결과 자료 |
| Demo / fixture UI | 예시 모드 | 실제 호스트나 외부 도구를 실행하지 않는 화면 예시. 호스트 상태에서는 데이터 출처를 ‘예시 데이터’로 표시 |
| Vault | 금고 | Ghost가 쓰는 로그인·카드·연락처·비밀 값을 보관하는 곳. 값은 다시 보여 주지 않고 ‘저장됨’으로만 표시 |
| Secure form | 금고 요청 | Ghost가 금고 값을 요청하는 확인할 일. 값은 채팅이 아닌 이 양식으로만 전달하고 버튼은 ‘금고에 전달’ |
| Browser handoff | 브라우저 대기 | Ghost가 Mac의 Chrome 창을 넘겨 사용자가 직접 처리하기를 기다리는 확인할 일. 끝내는 버튼은 ‘다 했어요’ |

## 문구 기준

- 같은 대상과 동작에는 같은 이름을 쓴다. 메뉴·제목·검색·접근성 이름을 함께 맞춘다.
- 버튼은 ‘일 맡기기’, ‘검토하기’, ‘결과 확인’, ‘일시정지’, ‘재개’처럼 실제 동작을 쓴다.
- 상태는 ‘진행 중’, ‘확인 필요’, ‘대기 중’, ‘완료’, ‘실패’, ‘취소됨’으로 표시한다. 구체적인 응답·협업·저장 상태는 별도로 명시한다.
- 설명은 ‘…합니다’, 안내는 ‘…해 주세요’로 쓴다. 짧은 빈 상태에는 ‘…없음’을 쓴다.
- 오류 안내는 확인된 결과와 가능한 다음 동작을 말한다. 원인·재시도 성공·완료를 추정하지 않는다.
- 목표와 작업, 검토와 승인, 저장과 검수, 응답 취소와 작업 취소를 합쳐 표현하지 않는다.
- 제품명, 명령·필드·권한 식별자, URL, 수치·단위는 유지한다. 기술 식별자는 필요한 상세 정보에서 보여 준다.

이 기준은 anti-slop의 D25(용어와 동작 일관성), W12/W29(구체적인 표현), W21(의미 보존)을 따른다.
