## 수정과 보안 계약

src/collaboration.rs는 위조 inbox payload가 delivery rejected가 되면 오류 반환 전에 부모 failed 상태를 저장하고 먼저 완료된 정상 sibling artifact를 보존한다. 거부로 실패한 부모의 재시작/run은 남은 work를 새로 시작하지 않는다. 성공 aggregate는 여전히 검증된 두 completed 결과가 있어야 생성한다.

원래 계약은 worker별 독립 실행과 payload/권한 검증이며 cross-profile 실행 트랜잭션이 아니다. envelope와 host identity의 전체 사전 검증은 계속 유지하고 corrupt second envelope의 zero-call 회귀도 통과한다. 이전 실패 테스트의 batch zero-call 가정을 worker UUID별 실행 관측으로 바꿨으며, 단순히 기대값을 낮춰 통과시키지 않았다.

tests/collaboration.rs의 forged payload 검증은 첫/두 번째 worker 순서 둘 다 검사한다. 위조 worker에 실제 fixture write grant가 있어도 provider 호출0, task queued/UUID유지, outbox·effect0, 파일 미생성을 검증했다. 정상 sibling 완료 부분결과/hash/공개 CLI snapshot, 부모 failed, 재시작·중복·취소 이후 artifact 보존과 추가호출0도 검증했다. fixture ProfileStore는 각 scope 종료에서 drop해 writer-lock 재open 충돌을 제거했다.

기존 tests/acceptance.rs, src/store.rs/tools.rs/judge.rs는 첫 단위 SHA256 그대로다. 포맷은 변경된 lib/main/provider/protocol/collaboration 및 collaboration test만 적용했다. Cargo.toml/lock은 이전 checkpoint 그대로다. docs/collaboration-acceptance.md에 위 계약을 명시했다.

## 범위와 다음 항목

현재 복구 단위의 실행 blocker는 없다. native provider 설정/credential loader/live LLM, 사용자 key-file, 브라우저 권한, 금융, 배포, 서비스/스케줄러, 모델 다운로드·상주 로딩은 수행하지 않았다. OxiBrowser 저장소는 별도 task가 담당하므로 읽거나 편집하지 않았다.

Ghosts v1 전체 완료는 아니다. native provider/사용자 직접 연결은 native-provider-next.md의 별도 bounded 단위이고, 대화 history/자료 adapter/private transport/관리 앱 및 release는 v1-acceptance.md에 남아 있다. OxiBrowser 후속 통합은 correlation/cancel/timeout, 세션 격리, 관찰→행동→재관찰 및 사용자 handoff 계약을 맞추되 이번 core 복구에서 새 capability를 추가하지 않았다.
