# Lifetime contract — revision 1

Authority: infra `plans/ghost-implementation-spec.md`. This contract does not declare any release or product acceptance.

`schema.json`, `golden.json`, `bindings.ts`, and `src/lifetime_contract.rs` are coordinator-owned. Rust, Pi, worker, desktop and later Swift consumers must use the same golden envelope. Digest encoding is sorted-key UTF-8 JSON, no whitespace, integer numbers only; body digest is SHA-256. Actor comes from authenticated transport, not the JSON claim.

## First-wave interface

- Host: `src/host/lifetime/mod.rs` exposes `apply(conn: &rusqlite::Connection, envelope: &Envelope, principal: &str) -> anyhow::Result<Response>` and `snapshot(conn: &Connection) -> Result<Snapshot>`. Coordinator source supports private additive Host schema13; `migration-005.sql` remains the frozen wire base. Migration6 stores correlated receiver receipts and trusted verifier/policy; migration7 adds registry, recipient mailbox and opaque notifications. Canonical conversation/controller migrations preserve that base; migration13 adds immutable report/reply correlation. Revision-1 bindings retain base migration5. No migration resets ACK bits or redispatches legacy intents. Runtime rollout is separate from source.
- Host body `goal.submit`: `ghost_id`, `conversation_id`, `prompt`, `privacy`, `acceptance_spec`. Creates one goal/work, immutable command receipt, runtime binding and Pi outbox atomically. Reply conversation is the request conversation. Same envelope ID and digest returns original IDs. Changed actor/epoch/body is conflict. Registry/profile existence is checked by coordinator façade before admission. `local_only`/`private` never enter external model context.
- Host body `goal.inspect`: `goal_id`; `goal.update`: `goal_id`, `prompt`, `acceptance_spec`, envelope expected revision. `work.submit`: `work_id`, `spec: WorkerSpec`; one immutable execution handle, worker outbox. `work.inspect`, `work.steer`, `work.cancel`: `work_id`, optional `prompt` for steer; `work.result`: `execution_id`, `producer`, `sequence`, `goal_revision`, `state`, `artifacts`, `summary`. Sequence digest dedup, late/cancelled/stale results retained but not accepted. `work.accept`: `acceptance: Acceptance`; all required checks and current revisions required. `snapshot` returns typed Snapshot.
- Outbox records have target `pi` or `worker`; body carries method, IDs and immutable command body. Coordinator owns async pump/ACK and never holds Host mutex/SQL transaction across child process/model I/O. A provides `pending_outbox(conn) -> Result<Vec<OutboxItem>>`, `ack_outbox(conn, id, receipt: &Value) -> Result<()>`; `OutboxItem { id: i64, command_id: String, target: String, payload: Value }`. ACK only after durable receiver receipt, retry same ID inspect first.
- Producer states cannot include `accepted`. Only owner verification with the current requirement, goal revision, trusted verifier/policy revision, attached producing-attempt artifact and independently passing checks commits acceptance. Acceptance records are immutable. Terminal result admission and owner acceptance each enqueue a separate report to the original conversation in their same Host transaction; no artifact contents are copied into those model-bound reports.
- Canonical work reports: `canonical-work-reports-v1.json` authenticates `report.inspect`/`report.reply` against one original Pi outbox delivery and its exact current canonical Owner Goal/conversation. A report is a Ghost advisory with no Owner `source_turn_id`, never acceptance authority. `text_digest` is lowercase SHA-256 of the exact UTF-8 reply bytes, without normalization. Same report/text returns the original reply; changed text conflicts. Pi persists report origin separately, queues behind active Owner control, and projects completed SDK entries before considering new model admission. Root startup reconciles an already-ACKed legacy report from its exact original envelope without resetting ACK or SDK identity.
- Goal assignments: `goal-assignment-v1.json` binds `conversation.assignment` and the trusted `conversation.assignment.inspect` callback to one committed Owner Goal or delegated child Work, its current revision, ancestry and immutable prompt. Pi persists a canonical assignment and one SDK task without an Owner submission/reply. It rechecks Host authority before model admission, reserves the conversation during inspection, and reconstructs current tool declarations without disclosing earlier Owner messages. Foreign Work, altered prompts and duplicate Goal mutations are denied at the Host-tool boundary. Existing canonical work-report identities and migration13 remain unchanged.
- Pi JSONL request: Envelope, `body.method` is `conversation.ensure|submit|inspect|status|steer|cancel_turn` or `runtime.reconcile`. Fields: `ghost_id`, `conversation_id`; submit adds `prompt`, `privacy`, `goal_id`, `goal_revision`; status adds the original receiver `request_id`; steer adds `prompt`. Response uses shared `Response.data`, including correlated command/conversation/Ghost identity and a resolved durable storage locator. Inspect and bounded committed submission status never resume work; explicit reconcile resumes pending SDK tasks. Active task graph omission never means success. Host requires explicit `GHOST_LIFETIME_MODE=fixture|broker`. Host tool transport discovers and authenticates the configured Host root, not a model-provided URL. Stable invocation IDs derive from Pi conversation/task/call IDs.
- Worker: `src/worker/mod.rs` public `Supervisor` owns separate `worker.db` and spawned process, not Host/client lifetime. `Supervisor::open(root: &Path) -> Result<Self>` and `handle(&mut self, request: &Envelope) -> Result<Response>`; optional async methods for process operations must be reported to coordinator. Request body method `submit` adds `spec: WorkerSpec`; other methods use `execution_id`; events adds `after_sequence`; steer adds `prompt`; acknowledge adds `through_sequence`; fence adds `new_epoch`. Local server/runner subcommand registration belongs to coordinator. Journal commit, process-start barrier, recovery and sequence spool are worker-owned. Fake process has explicit executable fixture; real execution is separate C2 gate.
- Native unknown collection: `native-unknown-collection-v1.json` permits physical cleanup only for the original execution, recorded process birth/group, VM and cleanup lease scope. It rejects unresolved Host-tool effects, seals actual private partial SDK bytes, and durably records forensic collection before releasing the original lease pair. `collect` remains idempotent; `unknown` is never rewritten as completion, settled SDK history, a synthetic exit code or Goal acceptance.
- Original worker routing: `worker-origin-v1.json` keeps each immutable execution on its exact successful committed `work.submit` computer and privately recorded root/socket. Current grants cannot redirect historical observer/cleanup calls. Historical cleanup origins grant no new submission or steering permission; original-computer steering without a current grant fails closed.
- Real worker entry is pinned OMP 18.8.6 SDK under coordinator-selected Bun, package, entry and config paths (`GHOST_OMP_BUN`, `GHOST_OMP_PACKAGE_ROOT`, `GHOST_OMP_SCOPED_ENTRY`, `GHOST_OMP_CONFIG`). It creates no ambient tools, verifies exactly `canary_read`/`canary_write` and the exact requested model/max thinking before prompt, and grants only those two descriptor-relative bounded tools. Global approval bypass, fallback and automatic retries remain disabled. Task text is framed so RPC slash commands cannot select another model or dispatch local controls. Same-UID scoping is not an OS sandbox.
- Desktop: `apps/ghost-ui/src/lifetime/` only. Import shared bindings from `../../../../contracts/lifetime/bindings.ts` relative to that directory. Expose `LifetimeView` with explicit fixture/live transport mode and injectable typed client. Export `createLifetimeClient(transport, storage)`; transport supports `request(envelope) -> Promise<Response>` and `snapshot() -> Promise<Snapshot>`. Persist client command IDs before send. Facade uses `{type:"lifetime", envelope}` through existing authenticated control action, snapshot through `body.method:"snapshot"`. App/router/client entry registration belongs to coordinator. No UI build output is written into live served `dist`; canary output directory only.
- Scoped mobile: gateway `/mobile/v1/lifetime/snapshot|action` requires a scoped device key and explicit `GHOST_LIFETIME_AUTHORITY_EPOCH`; legacy owner keys keep their existing routes and do not silently gain lifetime authority. The gateway authenticates and filters Ghost/conversation/capability scope, namespaces receiver command IDs by device, enforces payload/origin/rate limits and aborts on revocation. Artifacts require an in-scope producing execution; a shared content digest alone never grants visibility. Swift persists both IDs before sending, preserves unknown-outcome receipts, and retires a definitive success even when retry class is `same_id`, matching desktop semantics.
- Collaboration: `collaboration-v1.json` is the additive registry/mailbox/notification method contract. Host validates registry profiles in its authenticated façade, dispatches through the existing deduplicated transaction and emits terminal-result/acceptance notification rows atomically with their authoritative writes. Mailbox reads do not mark seen; ACK is monotonic; mailbox content never automatically enters model context. Child delegation, handoff/wait graph and selective room wake are distinct later gates, not claimed by mailbox source.
- Independent artifact verification: `operations::artifact_verifier::verify_artifact` runs outside the worker, binds the exact execution-specific immutable locator and verifies trusted expected raw bytes and SHA-256 through bounded no-follow streaming reads. It rejects forged metadata, links, unsafe file types and detected replacement. Producer pass flags never substitute for this invocation; verification is point-in-time, not a promise that the path cannot later change.

## Home privacy lanes (home-privacy-lanes-v1.json)

`contracts/lifetime/home-privacy-lanes-v1.json` isolates each Ghost's persistent worker HOME into two sibling lanes inside the registered `home_volume`: `public` (subscription-native model routes) and `private` (local routes; local may consume public-classified tasks but never writes the public lane). Only the selected lane child is mounted at `/home/ghost` — never the containing root or the sibling lane — selected solely from the trusted sealed backend. Fresh bindings provision both lanes (owner UID, 0700). Legacy unclassified home roots fail closed at `acquire_worker_home`, `worker_home_is_current`, and mount preparation until the operator runs `ghost computers migrate-home --config … --ghost … --computer … --confirm` with the worker stopped (no active or revoked process/collect lease, forged lanes refused): the migration records a byte/identity inventory on a durable attempt, renames every original into `private` (no deletion, no declassification, no source-to-live action), and an interrupted effect stays unknown — blocking all new lifecycle effects — until `ghost computers resolve-lifecycle` closes it with a verified outcome. Format-2 recovery preserves both lanes and originals byte-for-byte and reports restored legacy homes as requiring the same migration. See also the `mounts` clause in `native-workspace-v1.json`.

## Owned browser gate (owned-browser-v1.json)

`contracts/lifetime/owned-browser-v1.json` binds the owned per-Ghost browser to the same durable ComputerRegistry home, leases, and authority epoch as the native worker computer. Backend identity `ghost-owned-browser`, runtime `local-chromium`; the profile root is always the registry manifest's `browser-profile` scoped by the service's declared profile scope (`public` research profile with request-interception confinement, `private` authenticated profile for owner takeover only). Registry commands `attach_browser`/`detach_browser` fence the gate with grant-revision CAS; `lease kind=browser` requires a current attached service and stays single-writer. `accept_runtime` records per-epoch, probe-matched runtime facts (never caller-attested); `recreate`/`idle_stop` authorize only against them and execute only through the owning process via `lifecycle_effect`. The worker path exposes the scoped `browser` host tool (navigate/read/snapshot/screenshot only, confined) and requires exact owner-approved proposals with durable digest-bound receipts for every non-observational action. Recovery captures the master registry ledger plus per-computer home/browser presence (bundle format `ghost-recovery-bundle/2`); restore keeps dispatch off until explicit epoch-safe rebind plus `ghost lifetime accept --confirm`. See the contract for the full command, fencing, approval, and recovery rules.
